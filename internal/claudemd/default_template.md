## Working across these repos
- Each subdirectory is its own jj workspace: `cd` into it before running `jj`
  or that repo's build/test/lint commands. There is normally no VCS root at
  this level, so commands run here won't apply to any of the repos.
- These are colocated jj/git checkouts. Use `jj` for history operations —
  mutating git commands fight jj's automatic descendant restacking and create
  a second, drifting source of truth. In particular, never run `gh stack`
  `init`/`add`/`rebase`/`sync`/`modify`/`submit` here.
- Land and push changes independently per repo; keep each commit scoped to
  the repo it belongs to.
- If a change in one repo is a prerequisite for another (e.g. a library and
  its consumer, or a server and its client), land the dependency first, then
  update the dependent repo(s) to match.
- A single repo's tests passing is not sufficient — re-check the spec's
  Acceptance Criteria across all repos before calling the effort done.
