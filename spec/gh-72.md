# gh-72 — Concurrent agent sessions

**Issue:** https://github.com/dmihalcik-virtru/wgo/issues/72
**Resolves:** https://github.com/dmihalcik-virtru/wgo/issues/61
**Split from:** [gh-70](gh-70.md), which displays these sessions.

## Summary

Record each agent session under its own ID, so several agents can share a
workspace or an effort, and keep a live but quiet agent visible.

## Before this change

- `AgentSessions` is keyed by workspace root. Starting a second agent there
  overwrites the first, and `stop` removes the workspace's only session.
- `wgo .` calls `heartbeatAgent`, which detects the tool from environment
  variables and upserts by workspace root with no session ID.
- The same heartbeat calls `PruneStaleAgentSessions` under the state lock and
  deletes anything quiet for ten minutes (#61).
- The recorded PID is `os.Getppid()` of `wgo`. Under the statusline and under
  hooks, that is a short-lived shell, not the agent process.
- `store.Load` rejects any version below `StateVersion` with a "pre-jj, not
  migratable" error, and accepts versions above it silently.

## Requirements

### State model and migration

1. Key `AgentSessions` by stable session ID. Fields: `ID`, `ThemeID`,
   `Status` (working, waiting, idle; unknown only for migrated entries),
   `Source` (explicit, hook or inferred), `WorktreePath`, `RepoPath`,
   `Branch`, `Tool`, `StartTime`, `LastActivity`, and process identity (PID
   plus process start time) where available.
2. Bump `StateVersion` to 3. Migrate version-2 workspace-keyed entries into
   distinct IDs on load. Keep refusing version-1 state with the existing
   guidance.
3. A binary that loads state newer than it understands must refuse to write
   it, with an error that suggests upgrading `wgo`. Version-2 binaries
   predate that check, so version 3 stores `agent_sessions` as a JSON array
   (sorted by ID) instead of an object. A version-2 binary fails to parse it
   and never writes it, so an older binary on PATH, such as one invoked by a
   hook, cannot strip version-3 fields. Version 3 still reads the object form.

### Commands

4. `wgo agent start --session <id> --theme <effort>`. When `--session` is
   omitted, generate an ID and print it in a machine-readable form, so callers
   never parse the decorative status line.
5. `wgo agent heartbeat --session <id> [--status working|waiting|idle]`.
6. `wgo agent stop --session <id>`. An omitted session is accepted only when
   exactly one session exists in the current workspace. Otherwise list the
   candidates and suggest `--session`.
7. `wgo agent hook <event>` reads Claude Code hook JSON from stdin and uses its
   `session_id`. It never interpolates hook data into a shell command.
   `PostToolUse` means working, `Stop` means waiting for input, and
   `SessionEnd` removes the session.
8. Document the hook configuration under `contrib/`.

### Implicit heartbeat

9. The `wgo .` heartbeat refreshes a matching hook- or command-managed session
   for the same tool and workspace. It must not create a duplicate alongside
   one. With no explicit session, it keeps a single inferred session per
   workspace and tool, marked as inferred.
10. `wgo .` shows the most recently active agent for its single-agent glyph.
    `wgo agent status` lists all sessions.

### Liveness and pruning

11. A session with verified process identity, meaning the PID is alive and its
    start time matches, stays visible regardless of quiet time. This guards
    against PID reuse.
12. Record the agent's process, not the transient shell. Hooks should walk up
    to the tool process or use a PID the tool provides. When no reliable
    process identity exists, store none.
13. Without hook activity or process identity, show liveness as **uncertain**
    after the timeout instead of deleting the session. Inferred sessions may
    still expire on the timeout.
14. Pruning, wherever it runs, applies these rules. A bounded maximum age and
    manual `stop` prevent unbounded growth.
15. Flag two active sessions on the same repository and bookmark as a possible
    conflict, including sessions in different workspaces.

## Acceptance criteria

- [x] Two agents in one workspace survive independent heartbeat and stop.
- [x] Several sessions in one effort are listed and managed independently.
- [x] A quiet session whose agent process is alive does not expire after ten
      minutes (#61).
- [x] The statusline heartbeat neither duplicates nor clobbers hook-managed
      sessions.
- [x] Version-2 state migrates. Version-1 state is still refused with the
      existing guidance. An older binary cannot write version-3 state.
- [x] Claude Code hook JSON is parsed from stdin, never interpolated into a
      shell command.

## Verification

- Unit tests for migration, independent lifecycle, the PID-reuse guard,
  uncertain liveness, pruning rules and conflict detection.
- A hook adapter test with recorded Claude Code hook payloads.
- Reproduce #61: start a session tied to a live process, wait past the
  timeout with a fake clock, and confirm it is still listed.
- `go test ./...`, `go vet ./...`, `gofmt`.
