# gh-105 — Sprint view

**Issue:** https://github.com/dmihalcik-virtru/wgo/issues/105
**Epic:** [gh-96](gh-96.md) · **Wave 3** · Needs gh-98, gh-99 and gh-100; uses gh-97

**Question it answers:** "Does Jira agree with the code for this sprint, and
how far along is it against its goal?"

## Summary

One view per active sprint: its goal verbatim, the time elapsed, its tickets
with their linked PRs' states, and every place where Jira and the code
disagree (gh-99 mismatches). It replaces the manual sweep of "which tickets
are done but still open, and which are in progress with no PR".

## Requirements

1. An addon view `web/live-sprint.js`, registered as `sprint`. With several
   active sprints, a selector picks one (`sprint=` in the URL); the default is
   the sprint with the most tickets for the configured people.
2. Header:
   - sprint name, start and end dates;
   - a thin bar of elapsed time with "day 6 of 21";
   - the goal as plain text. When the goal is empty, the header says "no
     sprint goal".
3. Progress line: story points by status category as one horizontal bar
   divided into To Do, In Progress and Done. Each part is directly labelled
   with points and ticket count. Unestimated tickets are counted separately
   as "n unestimated", not as zero points.
4. Ticket table, grouped by status category, then assignee:
   - key and summary (linked);
   - assignee, points, status;
   - linked PRs as glyphs with refs: draft `◇`, open and awaiting review
     `○`, approved `✓`, merged `●`, closed `✕`. gh-99's move is on hover;
   - mismatch codes as short text with a `!` glyph.

   Rows can be selected, and the selection is shared with every view.
5. Clicking a mismatch code applies `mismatch:<code>` (gh-100). Clicking the
   progress bar's parts applies `status_category:<c>`.
6. The view respects the current query: tickets outside it are dimmed, not
   hidden, so the sprint stays whole. A toggle hides them instead.
7. "Copy as Markdown" (gh-100) on this view requests
   `/api/extract?view=sprint&sprint=<id>&q=<query>` and produces a sprint
   summary: goal, dates, points by category, mismatches with links, and the
   provenance footer. `wgo dash --md --view sprint --sprint ID --query EXPR`
   calls the same renderer. The selected sprint ID, active query and source
   freshness are included in both outputs.
8. With no `[jira] board`, or `jira_sprints` unknown, the view explains which
   is missing and how to configure it (`[jira] board = <id>`), instead of
   rendering empty.

## Out of scope

- Editing tickets or sprints.
- Burndown, velocity or forecasts.
- Sprints other than active ones (future sprints may follow).

## Acceptance criteria

- [ ] The fixture sprint renders goal, elapsed time, the progress bar with
      direct labels, and unestimated tickets counted separately.
- [ ] Each gh-99 mismatch in the fixture appears on its ticket and filters
      when clicked.
- [ ] The Markdown sprint summary matches a golden file and is byte-for-byte
      identical from the CLI and `/api/extract` for the same snapshot,
      sprint ID and query.
- [ ] Missing configuration and unknown sprint data produce the explanatory
      state.
- [ ] Keyboard-only use and a colour-vision-deficiency simulation pass
      (screenshots in the PR, light and dark).
- [ ] `go test ./...` passes.

## Delivery notes

- **Order.** The points bar, its labels, the ticket groups and the
  Markdown list Done, In Progress, To Do: done first, so the done share
  lines up with the elapsed-time bar of the same width above it. The
  table's columns are ticket, assignee, mismatches, linked PRs, points and
  status: beside gh-102's filters panel the view is narrow, and what it
  asks about stays in sight while points and status scroll.
- **Days.** "day N of M" counts calendar days in the snapshot's timezone:
  M from the start's day to the end's (so Jira's whole-week sprints are 7,
  14, 21 or 28 days), N from the start's day (day 1) to `generated_at`'s,
  at most M. Before the start it reads "starts in n days", after the end
  "day M of M, past its end". The bar is the exact share of time passed.
- **Which tickets the query shows.** A ticket is in the query when the
  query does not filter or the ticket is in its visible set (a match, or
  linked to or from one), so a PR clause such as `author:bob` shows the
  tickets those PRs link to. Tickets outside are dimmed (`outside=hide`
  hides them). The points bar always counts the whole sprint; the
  Markdown adds a line with the share the query shows, and lists only the
  mismatches on tickets it shows (with a count of the others).
- **Default sprint.** The most tickets assigned to a followed person,
  then the most tickets, then the earliest start and lowest ID. A ticket
  counts when its assignee's account ID is a followed person's Jira account
  ID, or when the sprint's ticket search (`assignee in (people)`) found it,
  recorded as `ticket.sprint_search`. It does not count when unassigned,
  when its account ID was compared with every followed person's, or when
  the sprint's complete search (`sprint.searched`, not truncated, everyone
  followed having a Jira identity) missed it. Otherwise it is unknown
  (`currentUser()`, an email; display names are not trusted), and while it
  is unknown for any sprint the default is the sprint with the most
  tickets; the selector's tooltip says so. The page does not write the
  default into the URL; Copy as Markdown always sends the sprint ID.
- **Explanations and errors.** No `jira_sprints` source, no board, board
  sprints unknown or failed, and a board without an active sprint each
  render an explanation (HTTP 200, exit 0), with the `[jira] board`
  snippet when the board is missing. A sprint ID that is not an active
  sprint is an error (HTTP 400, non-zero exit) listing the active ones.
  The rows view's `cols`, `group`, `layout` and `sort` are errors on the
  sprint view.
- **Copy as Markdown.** The view's `extract(ctx)` hook (gh-100's
  `registerView`) returns `{view: "sprint", sprint, cols: ""}`; live.js
  needed no change.
- **Fixture.** A second, parallel active sprint (Web Sprint 4, 1240, no
  goal) holds TEAM-107, so every gh-99 mismatch code sits on a sprint
  ticket and the selector has two sprints.
