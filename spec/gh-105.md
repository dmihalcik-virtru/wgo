# gh-105 — Sprint view

**Issue:** https://github.com/dmihalcik-virtru/wgo/issues/105
**Epic:** [gh-96](gh-96.md) · **Wave 3** · Needs gh-98, gh-99 and gh-100; uses gh-97

**Question it answers:** "Does Jira agree with the code for this sprint, and
how far along is it against its goal?"

## Summary

One view per active sprint: its goal verbatim, the time elapsed, its tickets
with their linked PRs' states, and every place where Jira and the code
disagree (gh-99 mismatches). It replaces the manual sweep of "which tickets
are done but still open, and which are in progress with no PR".

## Requirements

1. An addon view `web/live-sprint.js`, registered as `sprint`. With several
   active sprints, a selector picks one (`sprint=` in the URL); the default is
   the sprint with the most tickets for the configured people.
2. Header:
   - sprint name, start and end dates;
   - a thin bar of elapsed time with "day 6 of 21";
   - the goal as plain text. When the goal is empty, the header says "no
     sprint goal".
3. Progress line: story points by status category as one horizontal bar
   divided into To Do, In Progress and Done. Each part is directly labelled
   with points and ticket count. Unestimated tickets are counted separately
   as "n unestimated", not as zero points.
4. Ticket table, grouped by status category, then assignee:
   - key and summary (linked);
   - assignee, points, status;
   - linked PRs as glyphs with refs: draft `◇`, open and awaiting review
     `○`, approved `✓`, merged `●`, closed `✕`. gh-99's move is on hover;
   - mismatch codes as short text with a `!` glyph.

   Rows can be selected, and the selection is shared with every view.
5. Clicking a mismatch code applies `mismatch:<code>` (gh-100). Clicking the
   progress bar's parts applies `status_category:<c>`.
6. The view respects the current query: tickets outside it are dimmed, not
   hidden, so the sprint stays whole. A toggle hides them instead.
7. "Copy as Markdown" (gh-100) on this view requests
   `/api/extract?view=sprint&sprint=<id>&q=<query>` and produces a sprint
   summary: goal, dates, points by category, mismatches with links, and the
   provenance footer. `wgo dash --md --view sprint --sprint ID --query EXPR`
   calls the same renderer. The selected sprint ID, active query and source
   freshness are included in both outputs.
8. With no `[jira] board`, or `jira_sprints` unknown, the view explains which
   is missing and how to configure it (`[jira] board = <id>`), instead of
   rendering empty.

## Out of scope

- Editing tickets or sprints.
- Burndown, velocity or forecasts.
- Sprints other than active ones (future sprints may follow).

## Acceptance criteria

- [ ] The fixture sprint renders goal, elapsed time, the progress bar with
      direct labels, and unestimated tickets counted separately.
- [ ] Each gh-99 mismatch in the fixture appears on its ticket and filters
      when clicked.
- [ ] The Markdown sprint summary matches a golden file and is byte-for-byte
      identical from the CLI and `/api/extract` for the same snapshot,
      sprint ID and query.
- [ ] Missing configuration and unknown sprint data produce the explanatory
      state.
- [ ] Keyboard-only use and a colour-vision-deficiency simulation pass
      (screenshots in the PR, light and dark).
- [ ] `go test ./...` passes.
