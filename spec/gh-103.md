# gh-103 — Scatterplot and CI grid

**Issue:** https://github.com/dmihalcik-virtru/wgo/issues/103
**Epic:** [gh-96](gh-96.md) · **Wave 3** · Needs gh-97, gh-99 and gh-100

Two views, each answering one question.

## Scatterplot ("PR field")

**Question:** "Which PRs are small and have waited long — push them — and
which are big — split them?"

After Ahlberg & Shneiderman's FilmFinder starfield: every PR row of the
current query is a mark in a two-measure field, filtered live by the facets
(gh-102), with details on demand.

### Requirements

1. An addon view `web/live-scatter.js`, registered as `scatter` through gh-100.
   Marks are the query's PR rows.
2. Axes: x defaults to `waiting` and y to `size`. Either axis can be switched
   to any registered number or duration field; the choice is in the URL
   (`x=`, `y=`). Log axes are used for fields whose registry scale is `log`
   and for durations; zero is handled with a symmetric-log transform, and
   the axis title says "log scale". Gridlines are light, at readable steps (1,
   10, 100, 1,000 lines; 1, 7, 30, 90 days).
3. Encoding:
   - shape by `move` — circle reviewer, triangle author, square nobody,
     hollow ring unknown;
   - the accent colour only when the move is the operator's;
   - a small `×` overlay when `ci` is `failing`;
   - everything else neutral.

   A single compact key explains the shapes; no other legend.
4. Labels: direct labels (`acme/api#41`) for selected marks and for at most
   five outliers, by largest rank sum on the two axes. Other marks get a
   tooltip with ref, title, the two values, move and its evidence (gh-99).
5. Marks with an unknown value on either axis are not plotted at zero.
   They sit in a labelled "unknown" strip along that axis's edge.
6. Optional, off by default: thin dashed median lines for x and y of the
   current rows, each labelled with "median" and its value ("compared to
   what?").
7. Interaction:
   - drag a rectangle to select (Shift adds);
   - wheel or pinch to zoom, with a reset control;
   - click a mark to select it.

   The selection is shared with every view and facet (gh-100 store).
8. Accessibility: marks are reachable by keyboard in the table's sort order,
   and each has an `aria-label` with ref, values and move. The table remains
   the full alternative.
9. Under 1,000 marks render as SVG; above, canvas with a quadtree for hit
   testing (as the graph does, `internal/review/web/live.js:1080`).

## CI grid

**Question:** "Are these failures this PR's, or does the check fail
everywhere?"

### Requirements

10. An addon view `web/live-cigrid.js`, registered as `ci`, rendered as an
    HTML table (so it is accessible without a canvas) — one small multiple
    per repository, in the query's PR rows.
11. Columns are PRs, sorted by failure count, then number. Rows are check
    names that ran on at least one of those PRs, sorted by failures
    descending. Each cell shows that check's state on that PR's head:
    - failing: filled cell with `×`;
    - passing: faint `✓`;
    - pending: `·`;
    - skipped or neutral: blank, with an `aria-label`;
    - absent (the check did not run): empty.

    State is never shown by colour alone.
12. A row whose check is systemic in that repository (gh-99 `check_stats`) is
    labelled "fails everywhere — 5 of 6 PRs" and has a subtle background. A
    systemic row reads as a solid line, a PR's own failures as isolated cells.
13. Clicking a cell selects the PR and shows the check's link in the detail
    panel. Clicking a row header applies `check_failing:<name>` (gh-100).
    Clicking a column header selects the PR.
14. A repository with more than 60 PRs in the query shows the 60 with the
    most failures and "+n more", which narrows the query to that repository.
15. Truncated check lists (`checks_truncated`, gh-97) are marked on the
    column.

## Out of scope

- Check history across commits or re-runs.
- Fetching logs or annotations for failing checks.
- Re-running checks (a write).

## Acceptance criteria

- [ ] Scatter renders the fixture with log axes labelled, shapes by move,
      unknowns in the edge strip, and at most five outlier labels.
- [ ] Axis switching and brush selection update the URL and the shared
      selection; the table and facets reflect the selection.
- [ ] Pure functions (axis transforms, outlier choice, unknown partitioning,
      grid row and column ordering) are covered in
      `internal/review/testdata/live_logic.js`.
- [ ] CI grid shows the fixture's systemic check as a labelled solid row in
      one repository and not in another; a PR whose only failure is that
      check has no isolated failing cells.
- [ ] Row and cell clicks apply `check_failing:` and select the PR.
- [ ] Both views pass keyboard-only use and a colour-vision-deficiency
      simulation (screenshots in the PR, light and dark).
- [ ] `go test ./...` passes.
