# WGO-137 — PR cache must not cache a failed lookup as "no PRs"

## Summary

Stop `wgo` from recording a failed GitHub lookup as the authoritative answer
"this branch has no PRs". A failure must never overwrite a good cached result,
and a branch whose PR is momentarily unreachable must keep showing its
last-known-good PR line — annotated as stale — rather than silently showing
nothing.

## Problem / Motivation

Observed in `worktrees/pr-605-test-kas-uri-from-kao/opentdf/tests`: `wgo .`
printed no `pr:` line at all for a branch with an open PR
(`opentdf/tests#608`), while `wgo . --refresh` printed it correctly.

Two defects compose to produce this.

### 1. Every failure is laundered into "no PRs"

`ListPRsForBranch` (`internal/github/github.go:533`) converts every failure
into `(nil, nil)`:

- `!c.Available()` → `nil, nil` (line 534)
- slug resolution failure → `nil, nil` (line 538)
- `getJSON` error — 401, 403 rate limit, 404, 5xx, network error → `nil, nil`
  (line 545)

The transport already produces a precise, typed diagnosis of each of these
(`RateLimitError` with `ResetAt`, `APIError` with `StatusCode`, raw network
errors — `internal/github/transport.go:44-87`). All of it is discarded.

`prcache.fetchAndStore` (`internal/prcache/resolve.go:73-84`) only declines to
write when the fetcher returns a non-nil error, so it cannot tell "GitHub says
zero PRs" from "the call failed". It writes `{"prs": [], "fetched_at": <now>}`.

Reproduced:

```
$ GITHUB_TOKEN=<invalid> wgo . --refresh    # exit 0, no pr: line, no warning
$ cat ~/.wgo/cache/pr/opentdf-tests/test-kas-uri-from-kao-review-fixes.json
{"prs": [], "fetched_at": "2026-09-22T09:17:55-04:00"}
```

One transient API failure therefore pins "no PRs" onto a branch.

### 2. A cached empty list is served before it is rechecked

An empty list is a valid hit, so on `Stale` `Resolve` returns it immediately and
only schedules a background `_refresh-pr` (`resolve.go:49-57`). The invocation
in front of the user prints nothing; the *next* one is correct. Reproduced by
planting a stale `{"prs":[]}` entry: run 1 printed 0 `pr:` lines, the background
refresh healed the file within 6s, run 2 printed both PRs.

Together these read as a permanent bug rather than a cache artifact, and they
break the product principle that the PR link is always one click away.

## Proposed Solution

### 1. `ListPRsForBranch` returns real errors

Return the underlying error for slug-resolution and `getJSON` failures, and a
sentinel for the no-auth case, instead of `(nil, nil)`. The `Available()` guard
becomes an error return rather than a silent empty result, so a missing token is
diagnosable rather than indistinguishable from an unpushed branch.

`ListPRsForBranchEnriched` keeps its existing graceful degradation for the
*enrichment* calls (review decision, CI rollup): a PR with unknown CI is still
worth showing. Only the primary list call becomes fallible.

Out of scope: `ListPRsByBase` (`github.go:511`) has the same `(nil, nil)`
laundering and feeds stack enumeration rather than the PR cache. Tracked
separately.

### 2. The cache entry separates last-known-good from last attempt

```go
type entry struct {
    PRs           []models.PRRef `json:"prs"`
    FetchedAt     time.Time      `json:"fetched_at"`
    LastAttemptAt time.Time      `json:"last_attempt_at,omitempty"`
    LastError     string         `json:"last_error,omitempty"`
}
```

`PRs`/`FetchedAt` are only ever written by a *successful* fetch. A failure
writes `LastAttemptAt`/`LastError` and leaves the previous success intact.
Success clears `LastError`. The added fields are omitempty, so entries written
by the current release load unchanged.

`LastError` is persisted rather than kept in memory because the failing fetch
usually happens in the detached `_refresh-pr` child; the parent process that
later renders the line is not the process that saw the error.

Freshness is computed from `FetchedAt` (last success), so an entry holding only
an error is not mistaken for fresh data.

### 3. `Resolve` returns provenance, not just refs

```go
type Result struct {
    PRs           []models.PRRef // last successful result; nil if never fetched
    State         State
    FetchedAt     time.Time // zero if never successfully fetched
    LastAttemptAt time.Time // last fetch attempt, successful or not
    Err           error     // most recent failure, possibly alongside good PRs
}

func Resolve(f Fetcher, remoteURL, repoPath, branch string, opts Opts) Result
```

One value rather than `(refs, state, error)` because here the error is *data*:
Resolve legitimately returns good PRs and a non-nil `Err` together, and a
`(value, error)` signature invites callers to drop the value on error.

**Negative-result backoff.** `SyncOnMiss` must not turn a GitHub outage into a
synchronous 30s stall on every `wgo .`. When the entry has no successful fetch
but its `LastAttemptAt` is within the TTL, `Resolve` serves the recorded error
instead of re-fetching.

### 4. `wgo .` shows last-known-good, annotated

One new `models.Context` field (additive, no schema bump):

```go
PRLookup *PRLookupRef `json:"pr_lookup,omitempty"`

type PRLookupRef struct {
    FetchedAt *time.Time `json:"fetched_at,omitempty"`
    Error     string     `json:"error,omitempty"`
}
```

A nested pointer rather than two flat fields because a zero `time.Time` is *not*
omitted by `omitempty` (structs are never "empty" to encoding/json), so a flat
`prs_fetched_at` would appear on every healthy context. One nil pointer keeps
the common case byte-identical to today's output.

Provenance is attached only for a failure over non-current data: a failure a
fresh success has already superseded is dropped, or the warning would flicker as
background refreshes race the TTL.

Text rendering, after the `pr:` lines:

- PRs present, refresh failed:
  `pr:     ⚠ shown from 2 hours ago — refresh failed: github rate limit exhausted (resets …)`
- No PRs and the lookup failed:
  `pr:     ⚠ lookup failed: no GitHub credentials: set GITHUB_TOKEN or run `gh auth login``
- No PRs and the lookup succeeded: nothing (unchanged).

The cause is flattened to one line and clamped: a GitHub `APIError` embeds the
pretty-printed JSON response body, which would otherwise shatter the aligned
key-value rows. The cache and `--json` keep the untruncated text.

The PR line itself is unchanged and still hyperlinked — the point of the
exercise is that the link survives a failed refresh.

`wgo statusline` stays silent about failures: it is LocalOnly and must not grow
a warning that flickers once per prompt.

Out of scope, tracked as follow-ups: retry/backoff for transient classes in
`transport.RoundTrip` (there is none today), a per-error-class actionable
remedy table, and a GitHub auth/rate-limit check in `wgo doctor`.

## Acceptance Criteria

- [x] A `getJSON` failure in `ListPRsForBranch` propagates as an error instead of an empty list
- [x] With no resolvable token, `ListPRsForBranch` returns an error naming `gh auth login`
- [x] A failed fetch leaves an existing good cache entry's `prs` and `fetched_at` byte-identical, and records `last_error`
- [x] A failed fetch against a branch with no cache entry writes an error-only entry, not `{"prs": []}`
- [x] A successful fetch clears `last_error`
- [x] A cache file written before this change (no `last_attempt_at`/`last_error`) loads without error
- [x] `Resolve` with a stale-but-good entry and a failing fetcher returns the cached PRs *and* a non-nil `Err`
- [x] `Resolve` with `SyncOnMiss` and a recent recorded failure does not call the fetcher
- [x] `Resolve` with `SyncOnMiss` and a recorded failure older than the TTL does call the fetcher
- [x] `wgo .` renders the cached PR line plus a `⚠ … refresh failed` line when the refresh fails
- [x] `wgo .` renders `⚠ lookup failed: …` when there is no cached PR and the lookup fails
- [x] `wgo .` renders no warning line for a branch that genuinely has no PRs
- [x] The warning occupies exactly one row even when the cause is a multi-line JSON body
- [x] `wgo . --json` carries `pr_lookup` with the fetch time and error, and omits the object entirely when neither applies
- [x] `GITHUB_TOKEN=<invalid> wgo . --refresh` in a workspace with a known PR still prints the PR line, with the warning

Verified end-to-end in `worktrees/pr-605-test-kas-uri-from-kao/opentdf/tests`: after
warming the cache, `GITHUB_TOKEN=<invalid> wgo . --refresh` still printed the
`#608` and `#616` rows followed by `⚠ shown from just now — refresh failed: …
401 … Bad credentials`, and a subsequent authenticated refresh cleared
`last_error` and dropped `pr_lookup` from `--json`.
