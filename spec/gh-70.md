# gh-70 — Local live dashboard for ongoing work

**Issue:** https://github.com/dmihalcik-virtru/wgo/issues/70
**Depends on:** [gh-71](gh-71.md) (efforts and attribution), [gh-72](gh-72.md) (concurrent agent sessions)

## Summary

`wgo dash` serves a local view of work in progress, grouped by effort. It combines
jj workspaces and bookmarks, plan entries, PRs and tickets, and concurrent agent
sessions. A workspace's primary action opens a Ghostty **tab** at that workspace;
the user can also open an editor, reveal it in Finder, or open its plan/spec.
The page shares the review explorer's graph, table and visual language, and
links current efforts to past review runs when evidence overlaps.

## Delivery status

Slice 1 is implemented: the cached snapshot builder (`internal/dash`), the
GitHub issue cache (`internal/issuecache`), PR `updated_at` and requested
reviewers in `prcache`, the "since last look" baseline, a read-only
`dash.Handler` with a Host check and a placeholder page, and
`wgo dash --json [--days N] [--refresh]`. `--refresh` fetches missing or stale
data synchronously, ignoring leases, and skips integrations that are not
available (no GitHub credentials or gh, no acli). A repo without a GitHub
remote never queues PR or issue lookups. Nothing yet calls `Dash.Acknowledge`,
so the baseline does not advance outside tests until the UI exists.

Not yet delivered, so the acceptance criteria below remain open: the served
web UI, `wgo dash` without `--json`, `--port`/`--no-open`, the token, Origin
and action endpoint, launchers, the `wgo://` handler, and review cross-links.
This PR must not close gh-70.

## Baseline before this work (historical)

The notes below describe the code before gh-70. gh-71 attribution, gh-72
session liveness, and the GitHub issue and reviewer caches have since landed
and are consumed by slice 1.

- Efforts are not parsed or populated, and saving the plan drops unknown
  sections. [gh-71](gh-71.md) fixes this and provides workspace → effort
  attribution. The dashboard only consumes it.
- Agent sessions are keyed by workspace root and expire after ten quiet
  minutes (#61). [gh-72](gh-72.md) introduces session-ID keyed sessions and
  liveness. The dashboard only displays them.
- `internal/status.Collector` already discovers jj workspaces and gathers
  local activity. `prcache` and `jiracache` persist status across invocations,
  but GitHub issue status and review-request changes are not cached yet.
- `internal/review/web` has a force graph and sortable table. Its JavaScript
  is tailored to a historical person/PR graph, and the promised small
  multiples are not implemented. `review.Render` produces a static HTML file.
- No shared launcher or browser action endpoint exists yet (#27 is a design,
  not an implemented dependency). This spec includes the minimum shared
  launcher needed by the dashboard and leaves `wgo add` flag behavior to #27.

## User experience

```text
wgo dash                         # serve at http://127.0.0.1:8766/ and open browser
wgo dash --no-open               # serve without opening a browser
wgo dash --port 8767             # explicit port if the default is occupied
wgo dash --days 14               # activity small multiple window
wgo setup url-handler            # optional macOS wgo:// applet
```

The initial view lists active efforts with their description, workspaces,
bookmark/stack position, PR CI and review state, tickets, agents, and a
"Since last look" summary. A graph connects effort → workspace → PR → ticket
and effort → agent (with agent → workspace). The sortable table and all
actions work without the canvas. Small multiples show daily local activity,
PRs by state, and agent counts by effort; selecting a bar filters the graph
and table together. The page marks stale or unavailable remote data visibly.

The main workspace action is **Open tab**. **Resume agent** is a separate,
explicit action and is shown only for supported, user-configured tools. An
unavailable Ghostty falls back to a configured terminal launcher and then a
copyable, shell-quoted `cd` command; a missing optional integration never
prevents the rest of the page from loading.

## Data contracts

### Efforts, attribution and workspace IDs

1. Group work with the attribution function from [gh-71](gh-71.md),
   including its ticket-ID fallback, **Ungrouped**, conflicts and
   diagnostics. The dashboard never rewrites `.plan` and never infers a theme
   from a similar name.
2. Workspace IDs are deterministic opaque IDs derived from canonical workspace
   root plus main clone identity; labels use the configured workspace slug and
   repo name. An ID, rather than an HTTP path or an unqualified slug, is what
   every action and optional URL handler receives. Resolve the ID against
   the *currently discovered* workspace set before every action.

### Live snapshot

Add a dashboard snapshot model separate from `review.Graph`, with stable IDs,
nodes, edges, freshness metadata and precomputed daily/state counts. Extend
the shared explorer renderer with a `mode` and per-kind presentation rather
than making the historical graph pretend that agents are people. Keep the
existing `wgo review graph` JSON schema and offline HTML behavior intact.

- Local fields come from `discovery.FromConfig`, jj read queries, parsed plan,
  and store. A collector runs outside HTTP requests and uses jj's
  `--ignore-working-copy` read mode so viewing the dashboard cannot snapshot
  or rewrite user workspaces. It indexes by main clone and workspace path,
  deduplicating workspaces discovered twice. Limit/constrain concurrent jj
  calls and surface a per-workspace error instead of blocking the whole view.
  Derive stack position from the local jj change DAG; a PR base is display
  metadata, not the authority for stack topology.
- PRs come from `prcache` and the existing enriched branch fetch. Extend
  cached `PRRef` compatibly with `updated_at` and requested reviewers, or add
  a keyed companion cache. Jira comes from `jiracache`. Add a small GitHub
  issue cache keyed by repository and issue number for `gh-N` tickets. Cache
  reads never synchronously call GitHub, Jira or `gh`; misses are **unknown**,
  not "no PR" or "closed issue". Existing leases/backoff trigger background
  refresh with a bounded worker queue.
- Persist the last good snapshot atomically under `~/.wgo/cache/dash/`. On
  launch, load it into memory immediately and refresh local and remote data in
  the background. The HTTP read path serializes an immutable in-memory
  snapshot; browser polling (or SSE) swaps generations without full-page
  reload. If there is no snapshot yet, serve the page with a loading/empty
  state immediately. `GET /api/snapshot` in that state answers HTTP 200 with
  `{"status":"loading"}`: it is a polled status resource, so clients read the
  body's `status` rather than the HTTP code. Invalidate stale workspace actions even if the displayed
  snapshot has not updated yet.
- `GET /api/snapshot` and `GET /` do no discovery, jj query, network access or
  process launch. Target p95 response time below 100 ms for a warmed snapshot
  representing 100 workspaces and 300 PR/ticket/agent nodes, measured from a
  local HTTP client. Render the summary/table within 100 ms of receiving the
  cached payload in a browser test; the force simulation may continue after
  first paint. Record snapshot age and per-source freshness.

### Since last look

Store a compact baseline under `~/.wgo/cache/dash/last-seen.json`: each
workspace's visible jj change IDs (not mutable commit hashes), each PR's
state, review decision and requested reviewers, and the acknowledged snapshot
generation. Compare the latest snapshot to this baseline to show new changes,
PR state changes and newly requested reviews. A background refresh does not
advance the baseline. After the browser has rendered a snapshot, it explicitly
acknowledges that generation through an action endpoint; the current page
keeps its delta until it is closed or the user chooses **Mark seen**. A new
visit compares against the acknowledged baseline. A missing baseline shows
"No previous look" instead of inventing changes; an unavailable source shows
"Unknown". Bound the retained change IDs by a documented history window and
show a truncated count when older history is unavailable. Atomic writes
prevent a partial baseline from erasing deltas.

### Concurrent agent sessions

Read sessions from the [gh-72](gh-72.md) model. Show every session per effort
and workspace with tool, status, bookmark, start time, last activity and
liveness, including **uncertain**. Surface gh-72's same-bookmark conflict
flag. The dashboard never creates, heartbeats or stops sessions.

## Browser actions and launchers

The server binds **only** `127.0.0.1`, using the fixed default port 8766 so
offline review HTML can link to a stable local address. A busy port produces a
clear error and suggests `--port`; it never silently binds another address.
Generate a fresh cryptographically random action token per server launch,
embed it only in the served page, and keep it out of URLs, logs and referrers.
Every action is a POST with the token in a custom header. Reject missing or
incorrect tokens, `Origin` other than the exact server origin, foreign `Host`
headers (DNS rebinding), non-JSON content types, and unknown action names.
Set `Referrer-Policy: no-referrer`, a restrictive CSP, `Cache-Control:
no-store`, and no permissive CORS headers. GET routes are read-only. Do not
expose arbitrary filesystem reads or command execution through HTTP.

`POST /api/action` accepts `{ "kind": "terminal|resume|editor|reveal|plan|spec",
"workspace_id": "..." }`. The server resolves the ID afresh, verifies a
real, existing jj workspace under a configured discovery root, and obtains
the directory or plan/spec path itself. Spec lookup follows
`spec/<ticket>.md` in the associated repository. No request field may supply a path,
shell string, binary, AppleScript, or URL. Plan/spec actions open only files
already associated with that workspace; a missing file returns a helpful
message. For a plan entry, resolve its current line and open there when the
configured editor supports line navigation; otherwise display the matching
entry and offer the whole file. The editor action delegates to the shared
launcher from #27 (`code`, `xed`, or trusted local `--open` configuration);
reveal uses Finder on macOS.

On macOS, Ghostty's AppleScript `new tab in front window with configuration`
sets `initial working directory`. A fixed script receives the validated path
as an argument; it never interpolates a path into AppleScript source. Create
or activate a Ghostty window if none exists, then make the new tab active.
Resume is a separate action using a fixed tool allowlist (for example
`claude --continue`) selected from trusted local config, never from the
browser or a URL. If Ghostty/AppleScript is missing or fails, try a configured
terminal executable without a shell, then return a copyable `cd` command.
Report which fallback was used to the page; launch failure does not alter jj,
plan, or agent state.

Suggested config (defaults may be omitted):

```toml
[dash]
port = 8766
terminal = "ghostty"          # ghostty | iterm | terminal | command
terminal_command = ["wezterm", "start", "--cwd", "{workspace}"] # for command
resume = "claude"             # allowlisted tool, or empty to hide Resume
refresh_seconds = 30
days = 14
```

## Optional `wgo://` handler

`wgo setup url-handler` is an explicit macOS install step, independent of
`wgo dash`. It creates/registers a small applet with `osacompile` and a
`CFBundleURLTypes` entry for `wgo`; document an uninstall command. The applet
passes the entire URL to `wgo open <url>` as **one argument**. The CLI accepts
only `wgo://open?ws=<opaque-workspace-id>`: reject extra query keys, duplicate
`ws`, fragments, noncanonical encodings, raw paths, unknown/deleted workspaces,
and any command/resume parameter. Resolve the ID through current discovery,
then show a first-use macOS dialog containing the full path for that
workspace before launching. Store the accepted workspace ID and canonical
path together; path changes require confirmation again. The handler uses
the same launcher but does not need the dashboard's HTTP token. A non-macOS
build reports that URL-handler setup is unavailable without affecting `dash`.

## Review explorer cross-links

`wgo dash` serves historical review pages at `/review/<run-label>/...` using
the same embedded explorer assets. For a live effort, match its exact PR URLs
and ticket IDs against review run graph nodes; link to the newest matching
run's graph neighbourhood. Link a deep dive only when an explicitly named
file or exact evidence match identifies one. Never guess from a similar
theme title. Historical PR/ticket detail panels link forward to
`http://127.0.0.1:8766/lookup?entity=<stable-id>`, which resolves an active
effort and focuses it when `dash` is running. Static exported review HTML
keeps working offline; a forward link is simply unavailable when the local
server is stopped or running on a different port. The served historical view
uses the active port. Serve only paths beneath known review run directories,
with normalized run labels and no client-supplied filesystem path.

## Acceptance criteria

- [ ] `wgo dash` opens a loopback-only dashboard showing every active effort,
      its workspaces/bookmarks/stacks, PR CI/review state, tickets and every
      concurrent agent; orphan work is visible in Ungrouped.
- [ ] Efforts, Ungrouped work and attribution conflicts from gh-71 are shown,
      with ambiguity warnings visible.
- [ ] A warmed 100-workspace snapshot has p95 `/` and `/api/snapshot`
      responses under 100 ms; cold/offline requests return promptly with
      cached or loading data and never wait for network or jj.
- [ ] Graph, linked sortable table and three small multiples share selection
      and filters; the existing review export still works offline and its
      JSON schema is unchanged.
- [ ] Exact PR/ticket evidence creates two-way live/review links when a run
      exists; no false link is fabricated from a name match.
- [ ] "Since last look" reports new jj changes, PR state changes and new
      review requests against the last acknowledged generation, and clearly
      distinguishes missing remote data from no changes.
- [ ] **Open tab** creates a Ghostty tab in the selected workspace on macOS;
      **Resume** uses only a configured allowlisted tool. Editor, Finder and
      copyable-path fallbacks work independently.
- [ ] All action requests require the per-launch token and exact origin/host;
      cross-origin, malformed, path-injection and stale-workspace requests
      cannot launch anything.
- [ ] The optional `wgo://` handler opens only a currently known workspace ID,
      confirms first use, rejects URL-supplied commands, and can be removed.
- [ ] Two sessions in one workspace and several sessions in one effort are
      displayed independently, with uncertain liveness labeled.
- [ ] The page works without GitHub credentials, Jira, Ghostty, a review run,
      or the optional URL handler, with missing data/actions labeled clearly.

## Verification

- Unit tests for cache freshness, delta comparison, URL grammar and
  action target validation.
- `httptest` cases for bind address, token, Origin, Host, content type, CORS,
  DNS-rebinding, stale IDs, and path traversal; fake launcher asserts no
  rejected request starts a process.
- Browser tests for linked graph/table/small-multiple selection, keyboard
  navigation and both review/live modes. Run a real offline review export to
  catch regressions.
- macOS manual smoke: Ghostty with and without an existing window, missing
  Ghostty fallback, a path containing quotes/spaces, URL handler install,
  confirmation and uninstall. Run `go test ./...`, `go vet ./...`, and the
  repository's formatting/CI checks before opening a PR.

## Out of scope

- Mutating jj state, plan entries or GitHub/Jira from the dashboard.
- Arbitrary command strings or filesystem paths in browser/`wgo://` links.
- Synchronizing state across machines or exposing the dashboard on a network.
- Automatically generating year-in-review reports or guessing semantic theme
  equivalence from names.
