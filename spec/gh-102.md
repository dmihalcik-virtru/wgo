# gh-102 — Linked filters, saved filters, time and people

**Issue:** https://github.com/dmihalcik-virtru/wgo/issues/102
**Epic:** [gh-96](gh-96.md) · **Wave 3** · Needs gh-99 and gh-100; uses gh-97 and
gh-98 fields

**Question it answers:** "Which items have *this* combination of properties —
and what am I excluding?"

## Summary

Replace the single toggle filter with a panel of dynamic-query controls
(Ahlberg & Shneiderman): every facet is a small histogram that is also its
own filter, and each shows what the *other* filters leave over a grey ghost
of the full distribution (Spence & Tweedie's Attribute Explorer), so the
operator sees near misses and the cost of each constraint. Add a brushable
time range, people facets, an attention summary at the top left, and saved
filter chips. Every change is instant and undoable.

## Before this change

- Three small multiples — local activity per day, PRs by state, agent
  sessions by effort — each set a single `{by, value}` filter
  (`internal/review/web/live.js:721`). Bars show totals, with an inner accent
  bar for the selection's share.
- After gh-100, chart clicks set query clauses, and saved filters exist in
  config and the bootstrap, without a UI.

## Requirements

### Facet panel

1. A panel (addon `web/live-facets.js`) to the left of the views lists
   facets from gh-100's field registry. The default order is move, CI, PR
   state, repo, author, reviewer, waiting, age, size, ticket status, sprint,
   mismatch; `[dash] facets` overrides it. A "More filters" control adds any
   other registered field. Facets for fields with no known values in the
   snapshot are hidden.
2. **Enum and set facets**: horizontal bars, one per value, sorted by count
   (closed ordinal enums keep their order), each with:
   - a light ghost bar for the count in the whole snapshot;
   - a solid bar for the count under every **other** facet's clauses
     (coupling);
   - the count as text;
   - `unknown` as its own bar when present.

   Long value lists (repos, reviewers) show the top 8 and a type-ahead to
   find the rest.
3. **Number and duration facets**: a binned histogram (log bins when the
   field's scale is `log`; day bins for durations, with an open last bin),
   ghost and coupled counts per bin, and a two-handle range slider under it
   with numeric inputs for exact bounds.
4. **Date facets**: a per-day histogram over the window with a brush; the
   overview's local-activity chart is the `when` facet (gh-100) and is
   brushable.
5. Gestures, all also available by keyboard:

   | Pointer | Keyboard | Effect |
   |---|---|---|
   | click | Enter / Space | only this value (`field:v`); again clears |
   | Shift/⌘-click | Shift+Enter | add or remove `v` in the OR list |
   | Alt-click | Alt+Enter | exclude (`!field:v`) |
   | drag handles or brush | arrows, Shift+arrows | set range |

   Selected values show an outline and a check glyph; excluded values a
   strike and `✕` glyph — not colour alone. Each facet has a clear control,
   and "Clear all" resets the query.
6. Dragging updates the views live (`replaceState`); releasing commits a
   history entry (`pushState`), per gh-100.
7. A selection in any view shows as an inner accent bar in every facet's bars
   (today's `part` idiom), so the selection's distribution is visible against
   the filtered one.

### Time

8. Brushing the activity/`when` chart sets `when:a..b`. If the active query
   is `shipped`, brushing replaces its `merged:-7d..` clause with
   `merged:a..b`, so any selected week answers "what shipped between a and
   b". A merged PR's `when` date is its merge date (gh-100), even if it was
   updated later.
9. When a `when` or `merged` range is active, the attention summary and
   PR-state chart show the previous period of equal length as text beside the
   current value ("12 merged · previous 8"), from gh-97's closed-recent data.
   If the previous period is not fully covered by the data, it says so
   instead of showing a partial number.

### People

10. `author` and `reviewer` facets (reviewer = requested from or reviewed by)
    list the configured people first, by display name, then others by
    count. "Review load" is the reviewer facet's distribution over the
    current filter.

### Attention summary

11. The top-left panel shows three counts, each a link that applies its saved
    filter: **your move** (`my-move`), **waiting on reviewers**
    (`waiting-reviewers`) and **nobody's move** (`nobody`). It uses the accent
    colour only for "your move". Below it, at most two overview charts: the
    brushable activity/`when` chart and PRs by state. The agent-sessions
    chart stays only when any agent session exists. The layout keeps at most
    three charts besides the facet panel ([gh-96](gh-96.md) principle 10).

### Saved filters

12. A row of chips shows the saved filters (built-in and `[dash.filters]`);
    the chip matching the current query is marked. Choosing a chip replaces
    the query (one history entry).
13. "Copy as config" copies a `[dash.filters]` TOML line for the current
    query, with a placeholder name. The dash never writes config.

### Performance

14. With 2,000 nodes and 12 facets, any facet change re-renders the facets
    and the active view in under 100 ms. Coupled counts reuse gh-100's value
    index (for example one bitset per clause and per facet value), not a
    re-scan per bar. Numbers in the PR.

## Out of scope

- OR across facets, or parenthesised logic (gh-100 grammar is AND of OR-lists).
- Writing saved filters from the browser.
- Charts other than facets and the two overview charts.

## Acceptance criteria

- [ ] Each facet type renders ghost and coupled counts from the fixture; a
      test of the pure counting function checks that a facet's coupled
      counts ignore its own clause and honour all others.
- [ ] Every gesture in the table works by pointer and keyboard and produces
      the gh-100 clause shown.
- [ ] Brushing the activity chart sets `when:a..b`; from `shipped` it
      replaces `merged:-7d..` with `merged:a..b`. A week outside the last
      seven days lists exactly the fixture's PRs merged that week, including
      one updated later. The previous-period text is correct or says the
      data does not cover it.
- [ ] The attention summary counts equal the counts of their saved filters.
- [ ] Back and forward step through committed facet changes.
- [ ] No state is shown by colour alone (screenshot review in the PR, light
      and dark, plus a colour-vision-deficiency simulation).
- [ ] Facet change latency at 2,000 nodes is under 100 ms (numbers in the PR).
- [ ] `go test ./...` passes.
