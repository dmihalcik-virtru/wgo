# feat(jira): replace acli with twg across wgo and year-in-review

## Summary
## Problem

`wgo` and its bundled `/year-in-review` skill currently shell out to `acli` for all Jira operations (`internal/jira`, `wgo dash`, `wgo standup`, `wgo add`, `wgo spec jira`, and `.claude/skills/year-in-review/collect.py`). On machines that use `twg` (`~/.local/bin/twg`) instead of `acli`, Jira features degrade or fail (`acli not on PATH` / `FileNotFoundError: 'acli'`).

Beyond availability, `acli` imposed several limitations and workarounds documented in `internal/jira/facts.go` and `spec/gh-98.md`:
- `acli jira workitem search --fields` rejected `components`, `parent`, `resolution`, `resolutiondate`, `created`, `updated`, and `customfield_*` IDs client-side before sending any request, and returned `[null, ...]` when `--fields key` was requested alone.
- `acli` provided neither a field-metadata command nor `--expand names`, so `DiscoverFieldIDs` could only infer `Sprint` by JSON shape and could not auto-discover `Story Points`, `Team`, or `Epic Link`.
- `acli` had no batch issue fetch, spawning one subprocess per ticket during `wgo dash --refresh` and `year-in-review` collection.
- Auth, site-host detection, and pagination relied on scraping plain text (`Site: ...`, `unauthorized: use 'acli jira auth login'`) and concatenated JSON documents.

## Scope

Replace `acli` with `twg` across the `wgo` Go codebase and bundled skills/agents:
- Resolve `twg` on `PATH` with a fallback check for `$HOME/.local/bin/twg` when `PATH` omits `~/.local/bin`.
- Invoke `twg` non-interactively with `TWG_AGENT_DEFAULTS=1` and explicit `-o json --output-summary none` (plus `--site <cfg.Jira.Site>` when `[jira] site` is set).
- Update `internal/jira`, `internal/cmd`, `internal/dash`, `internal/config`, tests (`fakeTwg` fixtures captured/modeled on `twg` `apiVersion: "v2"` envelopes), `.claude/skills/year-in-review/collect.py`, `.claude/skills/*/SKILL.md`, `.claude/agents/yir-*.md`, and `README.md`.

## Verified `acli` → `twg` Mapping (`apiVersion: "v2"`)

| Capability | Current `acli` usage | Replacement `twg` command & contract |
| --- | --- | --- |
| Default site host (`SiteHost`, `jira_site`) | `acli jira auth status` (`Site: <host>` regex) | `twg auth profile list -o json --output-summary none` → local read of `data.defaults[data.activeEnvironment]` → `data.profiles[].site` (no network call); `twg` workitem payloads also carry `url` (`https://<site>/browse/<KEY>`) directly |
| Live auth check & circuit breaker (`CheckAuth`, `LoginStatus`, `IsAuthError`, `jirapause`) | `acli jira auth status` + stderr string matching | `twg whoami -o json --output-summary none` (`data.accountId`, `data.email`); parse structured error envelopes (`{"ok": false, "error": {"code": ..., "kind": ..., "message": ...}}`) and point remediation to `twg login` / `twg doctor` |
| Single issue read (`GetIssue`, `GetIssueJSON`) | `acli jira workitem view <KEY> --fields ... --json` | `twg jira workitem get <KEY> --fields <fields>` (or `--full` for `*all`) → `data[0]`. **Schema note:** `twg` flattens issue fields onto the workitem object (`data[0].summary`, `data[0].status`, `data[0].customfield_*`, `data[0].url`) instead of nesting under `fields` (`parent.fields` remains nested) |
| Batch issue hydration (`dash` refresh, `collect.py`) | 1 subprocess per key (`workitem view`) | `twg jira workitem bulk-get <KEY...> --full` (or `--fields ...`) → `data.items[]: {input, ok, data, error}`, replacing N subprocesses with batched Jira REST bulkfetch calls |
| JQL search (`SearchIssues`, `SearchIssuesJSON`, `jira_keys`) | `acli jira workitem search --jql <jql> --fields ... --paginate --json` | `twg jira workitem query --jql <jql> --fields <fields> --limit <N> [--after <cursor>]` → `data.issues[]` + `pageInfo.{hasNextPage, nextCursor}`. Verified to accept `components,parent,resolution,resolutiondate,created,updated` and `customfield_*` directly without client-side field blocks or `[null]` arrays |
| Custom field ID discovery (`DiscoverFieldIDs`) | Shape-only heuristic on `Sprint`; manual `[jira.fields]` required for others | `twg jira workitem field update-metadata --id <KEY>` → `data.fields[]: {id, key, name, schema}` (returns `Story Points`, `Sprint`, `Team` / `Team Assignment`, etc. with exact `customfield_*` IDs) |
| Board sprints (`ListSprintsContext`) | `acli jira board list-sprints --id <id> [--state s] [--paginate] --json` | `twg jira board sprints query --id <boardID> [--state active\|future\|closed] [--start-at <offset> --max-results <N>]` → `data.{sprints, total, isLast}` (query per state when multiple states are requested) |
| Comments & watchers (`GetComments`, `GetWatchers`) | `acli jira workitem comment list` / `watcher list` | `twg jira workitem comment query --issue-id <KEY> --first <limit> [--order-by +created]` (`data[]`) and `twg jira workitem watcher query --issue-id <KEY>` (`data.watchers[]`) |
| Issue mutations (`CreateIssue`, `UpdateIssue`, `TransitionIssue`) | `acli jira workitem create` / `edit` / `transition` | `twg jira workitem create --space <project> --type <type> --summary <summary> [--description <desc> --description-format markdown] --yes`, `twg jira workitem update --id <KEY> ...`, and `twg jira workitem transition --id <KEY> --transition-id <status>` |

## Acceptance criteria

- [ ] Every Go Jira operation in `internal/jira` (`CheckAuth`, `LoginStatus`, `SiteHost`, `ListSprintsContext`, `SearchIssues`, `SearchIssuesJSONContext`, `GetIssue`, `GetIssueJSONContext`, `GetComments`, `GetWatchers`, `CreateIssue`, `UpdateIssue`, `TransitionIssue`, plus batched `BulkGetIssuesJSONContext`) uses `twg` with `context.Context` cancellation and `WaitDelay`.
- [ ] `ParseFacts` handles `twg`'s flattened workitem JSON (while preserving `parent.fields` parsing), and `DiscoverFieldIDs` discovers `Story Points`, `Sprint`, `Team` / `Team Assignment`, and `Epic Link` via `twg jira workitem field update-metadata` (cached per site as today).
- [ ] Sprint ticket searches request full `Facts` fields directly via `twg jira workitem query --fields ...` and paginate cleanly via `pageInfo.nextCursor`.
- [ ] Missing `twg` (neither on `PATH` nor at `~/.local/bin/twg`) or unauthenticated `twg` degrades gracefully in `wgo statusline`, `wgo add`, and `wgo dash` (`jirapause` circuit breaker) with updated `twg` diagnostics, never blocking the `statusline` hot path.
- [ ] `.claude/skills/year-in-review/collect.py` uses `twg` (`auth profile list`, `jira workitem query`, and batched `jira workitem bulk-get`), and skill/agent docs (`.claude/skills/`, `.claude/agents/yir-*.md`, `README.md`) reflect `twg`.
- [ ] Unit and integration tests replace `fakeAcli` fixtures with `twg` v2 JSON envelopes covering success, pagination, custom-field discovery, missing binary, auth failure, and hanging subprocesses.
