# Support GitHub Issues in `wgo add`

## Summary

Let `wgo add` start a tracked jj workspace from an existing GitHub issue or create a new GitHub issue first. Use the issue title and body to scaffold the spec and link back to the issue.

## Inputs and behavior

- Existing issues accept `42`, quoted `#42`, `owner/repo#42`, `gh-42`, or a GitHub issue URL. A bare number resolves in the current jj repo, falling back to the first `-r` repo when outside a checkout.
- `--github` creates an issue in the current repo or first `-r` repo. `--github-labels` and `--github-milestone` apply to that issue.
- Both paths reuse the tracked `wgo add` jj workspace, bookmark, push, plan, and spec flow. The spec lives at `spec/gh-<number>.md` and includes `issue: <url>`.

## Acceptance Criteria

- [x] Existing issue inputs resolve and fetch the issue title and body before a workspace is created; missing issues and PR numbers fail clearly.
- [x] A new issue is created with optional labels and milestone, then a tracked workspace and spec are created.
- [x] The spec contains the GitHub issue URL and body; the branch/bookmark and plan use the `gh-<number>` ticket.
- [x] GitHub issue work does not probe Jira. Existing Jira ticket and scratch task behavior continues to work.
- [x] Focused tests cover parsing, GitHub API requests, and spec rendering; `go test ./...` passes.
