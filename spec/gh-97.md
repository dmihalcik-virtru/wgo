# gh-97 — PR inventory and PR facts

**Issue:** https://github.com/dmihalcik-virtru/wgo/issues/97
**Epic:** [gh-96](gh-96.md) · **Wave 1** · Unblocks gh-99, gh-101, gh-103, gh-104

## Summary

Bring every PR that the configured people author or are asked to review into
the dash snapshot, with the facts triage needs: age, size, mergeability,
per-check results, and reviews and review requests with their times. Today a
PR appears only when a local bookmark leads to it.

## Before this change

- `prcache` caches PRs per remote, repo and branch
  (`internal/prcache/prcache.go:281`). The collector queues one `JobPR` per
  bookmark (`internal/dash/remote.go:28`), so a PR without a local bookmark
  never appears.
- `models.PRRef` (`models/context.go:96`) holds number, title, state, URL,
  review decision, draft flag, a CI rollup of counts (`CIStatus`,
  `models/context.go:135`), `updated_at` and requested reviewers
  (`team:<slug>` for teams). `wgo .` and the statusline share it.
- `github.CLIClient.searchPRs` (`internal/github/prs.go:83`) calls REST
  `/search/issues` with `per_page=50` and **does not paginate**, so
  `ListMyOpenPRs` silently stops at 50. There is no GraphQL helper.
- In practice, GraphQL search pages of 50 PRs with nested reviews and checks
  intermittently return 502; pages of 20 with retries succeed.

## Requirements

### People

1. Add `[[dash.people]]` entries with `github` (login, required), `jira`
   (account ID, email or `currentUser()`, optional; used by gh-98) and `name`
   (display, optional). When none are configured, the list is the
   authenticated user (`CurrentUser`, `internal/github/prs.go:70`; Jira
   `currentUser()`) plus `[pair]`'s `teammate`/`teammate_jira`/`display_name`
   when set (`internal/config/config.go:192`). The authenticated user is
   always included. The query macro `@me` (gh-100) means the authenticated
   user.

### Inventory sets

For each person the inventory holds:

2. **open-authored** — every open PR, draft or not, authored by the person.
3. **review-requested** — open PRs on which the person, or a team they belong
   to, is a requested reviewer (`review-requested:<login>`; GitHub expands
   team membership).
4. **closed-recent** — PRs authored by the person that were merged or closed
   within `max(2 × days, 28)` days, so a period can be compared with the one
   before it (gh-102).

Archived repositories are excluded. A PR found in several sets is one node.

### Facts per PR

Extend `dash.PRInfo` (`internal/dash/model.go:209`) with optional fields:

| Field | Meaning |
|---|---|
| `author` | login |
| `created_at`, `merged_at`, `closed_at` | GitHub times; omitted when not applicable |
| `ready_at` | when the PR last left draft (latest `ReadyForReviewEvent`), else `created_at` if it was never a draft; omitted while draft |
| `additions`, `deletions`, `changed_files` | from GitHub |
| `mergeable` | `mergeable`, `conflicting` or `unknown`. GitHub computes this lazily, so `unknown` is common and does not mean "no" |
| `base_ref`, `head_ref` | branch names |
| `review_requests` | `[{reviewer, kind: "user"\|"team", requested_at}]`; `requested_at` from the latest `ReviewRequestedEvent` for that reviewer, omitted if none was found |
| `reviews` | latest review per reviewer: `[{author, state, submitted_at}]`, state one of `APPROVED`, `CHANGES_REQUESTED`, `COMMENTED`, `DISMISSED` |
| `checks` | head-commit check runs and status contexts: `[{name, state, url}]`, state one of `success`, `failure`, `pending`, `skipped`, `neutral`; at most 100, with `checks_truncated: true` beyond |
| `ticket_keys` | ticket IDs from the head branch (`spec.ParseTicketFromBranch` rules), then title, then body; ordered, deduplicated. Title and body matches count only for known prefixes (requirement 5) |
| `involvement` | every `{person, role}` pair, role one of `author`, `review_requested`, `reviewed` |
| `sources` | `bookmark`, `inventory`, or both |

Existing fields keep their meaning; `RequestedReviewers` and `ReviewersKnown`
stay, and `review_requests` adds kinds and times.

`models.PRRef` and `prcache` do **not** change: the statusline hot path keeps
its compact cache. The inventory is a separate cache.

5. A bare `[A-Z]+-\d+` scan of titles and bodies would read `SHA-256`,
   `AES-256`, `P-384` and `UTF-8` as tickets. Title and body matches are kept
   only when their prefix is known: `[dash] ticket_prefixes`, else the
   prefixes in `[jira] project`, `default_project` and `project_rules`, plus
   prefixes of tickets parsed from local bookmarks. `gh-N` and `#N`
   references to issues in the same repository are kept as GitHub tickets.

### Fetching

6. Add a GraphQL helper to `internal/github` on the existing authenticated
   HTTP client (`bodyJSON`, `internal/github/github.go:1050`): `POST
   /graphql`, typed errors for HTTP failures and for a GraphQL `errors` array,
   and partial data returned alongside errors. No shelling out to `gh`.
7. Fetch each set through the GraphQL `search` connection with `first: 20`,
   following `pageInfo.endCursor` to the end. Retry a page on 5xx or timeout
   up to 3 times with exponential backoff (1 s, 2 s, 4 s); then fail that set
   and keep its last good data as stale.
8. GitHub search returns at most 1,000 results. When `issueCount` exceeds
   that, mark the set `truncated` and add a diagnostic.
9. Fix `searchPRs`'s silent truncation: follow REST pagination (or delegate
   to the GraphQL path) so `ListMyOpenPRs` and `ListInvolvedPRs` return every
   result.

### Cache and refresh

10. New package `internal/inventory` caches each (person, set) under
   `~/.wgo/cache/inventory/` with `fetched_at`, `last_attempt_at` and
   `last_error`, and leases like `prcache.LockRefresh`. TTLs come from `[dash]
   inventory_ttl_seconds`: default 300 for open sets and 1800 for
   closed-recent.
11. A new `dash.JobKind` `inventory` runs through the existing `Refresher`
    (`internal/dash/remote.go:91`). `wgo dash --json --refresh` refreshes the
    inventory synchronously, like the other sources.
12. A new source `github_inventory` in `Snapshot.Sources` reports freshness per
    set, `OldestFetch`, truncation and errors. With no token and no `gh` it is
    `unknown` with the existing "no GitHub credentials" detail, and the rest
    of the dash works.

### Attaching PRs to the graph

13. A PR found through a bookmark keeps today's node ID
    (`prNodeID`, `internal/dash/ids.go:35`) and edges. Inventory facts merge
    into that node, keyed by repository and number.
14. A PR found only by the inventory attaches, first match wins:
    1. to the bookmark of a workspace in the same repository whose bookmark
       equals the PR's head ref;
    2. to the effort whose key is `ticket-<id>` for any of its `ticket_keys`;
    3. to the effort of a workspace whose bookmark's ticket is one of its
       `ticket_keys`;
    4. to a per-repository group effort `repo:<owner/repo>` — a new group
       `repo`, ordered after ticket groups and before Ungrouped (Go
       ordering and `L.effortOrder`, `internal/review/web/live.js:294`).

    Cases 2–4 use a new edge kind `tracks` (effort → PR).
15. Ticket nodes are added for inventory PRs' `ticket_keys` exactly as for
    bookmarks (`internal/dash/assemble.go:370`), with an edge `pr → ticket`,
    queuing Jira and GitHub issue lookups.
16. `Counts.PRStates` includes inventory PRs. A new `Counts.Merged` counts
    merged PRs per day of the window, keyed by effort, so "shipped" can have a
    small multiple.

### Fixture

17. Add `internal/dash/testdata/analysis_fixture.json`: a sanitized snapshot
    (invented repos, people and tickets per gh-96) that exercises every field
    above — drafts, team-only requests, no reviewers, conflicts, unknown
    mergeability, a check failing on most PRs in one repo, merged and closed
    PRs, PRs in several sets — plus a generator test helper that scales it to
    2,000 nodes for performance checks. Later specs extend this fixture.

## Edge cases and constraints

- A PR authored by someone outside `people` that requests a review from a
  person is included through review-requested; `author` is the other login.
- Repositories the token cannot read: GraphQL returns partial data with
  errors. Keep the data and record the error on the source.
- A PR deleted or transferred between fetches simply disappears from the next
  fetch.
- Times are GitHub's; the page renders them relative to local now.
- Collection from a warm cache of 500 inventory PRs stays under 1 s and the
  snapshot under 5 MB.

## Out of scope

- Timeline histories beyond the two events used above (gh-104).
- Derived facts such as "whose move" (gh-99).
- Changing `prcache`, `PRRef` or the statusline.
- PRs of people who are not configured.

## Acceptance criteria

- [ ] With 195 open authored PRs, all 195 appear in the snapshot. Test: a fake
      GraphQL server serving 10 pages, with one transient 502 on page 4 that
      succeeds on retry.
- [ ] `ListMyOpenPRs` returns more than 50 PRs when more exist (fake server,
      3 REST pages).
- [ ] Every field in the facts table is populated from the fake server, and
      is omitted — not a misleading zero — when GitHub did not report it.
- [ ] A PR known through both a bookmark and the inventory is one node with
      `sources: ["bookmark","inventory"]` and an unchanged ID.
- [ ] Attachment follows requirement 14; a table-driven test covers each case.
- [ ] Without credentials the dash loads, `github_inventory` is `unknown` with
      a reason, and no request is attempted.
- [ ] A failed refresh keeps the previous inventory as `stale` with the error
      recorded.
- [ ] GET routes make no network calls (the existing purity tests,
      `internal/dash/handler_purity_test.go`, cover the inventory path).
- [ ] The sanitized fixture and its generator exist and pass dash
      validation (`internal/dash/validate.go`).
- [ ] `go test ./...` and `go vet ./...` pass.

## Verification

```sh
wgo dash --json --refresh | jq '.snapshot.sources.github_inventory,
  ([.snapshot.nodes[] | select(.kind=="pr" and .pr.state=="open")] | length)'
gh search prs --author @me --state open --limit 1000 --json number | jq length
```

The two open-PR counts match (modulo PRs opened between the commands).
