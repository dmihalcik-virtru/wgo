# WGO-135 — The mains clone is the trunk checkout

## Summary

`wgo to <trunk-url>` must resolve to the clone at `<mains_dir>/<owner>/<repo>`,
which already *is* the trunk checkout, instead of manufacturing a redundant
`<worktrees_dir>/<trunk>/<repo>` workspace that holds a second copy of the same
commit.

Work that has accumulated on a mains clone's `@` is reported, never moved
silently. A new `wgo park` relocates it to a proper feature workspace on demand.

## Problem

```
$ wgo to https://github.com/some-org/repo1.git
~/Documents/GitHub/worktrees/main/repo1      # wrong
                                             # want ~/Documents/GitHub/mains/some-org/repo1
```

`runTo` called `createWorktree` for every full URL, and the non-PR destination
is hardcoded to `<worktrees_dir>/<sanitized-branch>/<repo>`. A bare repo URL
parses as `URLTypeBranch` with an empty identifier, the GitHub default branch
fills that in, and the branch name becomes a directory.

The bug looked intermittent because step 4, `findExistingCheckout`, returned a
path only when the clone's nearest bookmark still equalled the branch. While the
clone's `@` sat on the default-branch bookmark the lookup succeeded and the
right path came back; once `@` drifted — a `jj new`, or work in progress — the
lookup missed and step 7 manufactured the junk workspace. The same command gave
different answers depending on unrelated state in the clone.

Two smaller defects in `runToLocal` shared the cause:

- With no branch, it returned the first `matchesRemote` hit from the discovery
  walk, which is routinely a secondary workspace under `worktrees_dir`.
- With a branch, it consulted `findExistingCheckout` before delegating, so
  `wgo to owner/repo@main` could return the junk workspace directly.

## Proposed Solution

### Trunk routing

`runTo` becomes a dispatcher. `URLTypeBranch` — which covers both bare repo URLs
and `.../tree/<ref>` — goes to `runToBranch`; PR and issue URLs keep the existing
flow byte-for-byte, since neither can ever name the trunk.

`runToBranch` reorders the steps, and the reordering *is* the fix:

1. `findOrCloneRepo` — first, because trunk identification needs local jj state.
2. `localTrunkBookmark` — resolved from `jj log -r trunk()` plus the origin
   bookmarks at that commit, so the answer is available offline.
3. Branch: the URL's identifier, else `resolveDefaultBranch`.
4. **If the branch is trunk**, print the clone and return.
5. Otherwise `findExistingCheckout`, then `createWorktree` — unchanged.

The trunk check must precede `findExistingCheckout`: that function matches any
workspace whose `@` carries the named bookmark, which includes the very junk
workspaces this change eliminates.

`isTrunkTarget` compares against the local trunk first and falls back to the
GitHub default-branch API only when jj cannot name one. A failed fallback
returns false, preserving the previous behaviour rather than guessing. It
deliberately does not consult `doctor.exclude_bookmarks` — that list contains
`release/*`, and `.../tree/release/1.2` is a real branch that needs its own
workspace.

`resolveDefaultBranch` also fixes a latent bug: a bare URL used to hard-fail
offline, and now falls back to the local trunk bookmark.

### `wgo park`

Moves in-progress work out of a mains clone into `<worktrees_dir>/<slug>/<repo>`.
Nothing is copied: jj workspaces share one repo store, so the work is claimed by
a new workspace and the clone's `@` is returned to trunk.

Not a `wgo doctor` fix — doctor is read-only across its whole surface and its
input set is `state.Repos`, not the cwd. Doctor reports; `wgo park` fixes.

## Acceptance Criteria

### Routing

- [ ] `wgo to https://github.com/<owner>/<repo>.git` prints
      `<mains_dir>/<owner>/<repo>` and creates nothing under `worktrees_dir`.
- [ ] `wgo to https://github.com/<owner>/<repo>/tree/<trunk>` does the same.
- [ ] The answer does not depend on where the clone's `@` currently sits.
- [ ] A non-trunk branch URL still yields `<worktrees_dir>/<slug>/<repo>`.
- [ ] PR and issue URLs are unaffected, including the stack-resolution path.
- [ ] A trunk checkout still runs `EnsureColocated` on the clone, as
      `createWorktree` did when it was that call's only caller.
- [ ] `wgo to owner/repo` (no branch) returns the main workspace root, not a
      secondary workspace the discovery walk happened to reach first.
- [ ] A bare URL resolves offline via the local trunk bookmark.
- [ ] `--on` is ignored on a trunk target, with a warning.

### `wgo park` I/O contract

- [ ] stdout is exactly one line, the destination path, so `cd $(wgo park)` works.
- [ ] stdout is empty for `--dry-run` and when there is no work.
- [ ] The plan and all progress go to stderr, rendered identically for
      `--dry-run` and the real run.
- [ ] Exit 0 on success *and* on "nothing to park"; non-zero on preflight abort
      or mutation failure.
- [ ] Flags: `--dry-run`, `--no-bookmark`, `--name <slug>`, plus the inherited
      persistent `-C/--repo`.

### What counts as outstanding work

Computed against the main workspace, with `CurrentChange` run inside it so jj
snapshots the working copy first:

- [ ] `(trunk)..(@)` is empty → no work.
- [ ] Exactly one change, empty, with a blank description → no work (the
      expected resting state).
- [ ] Anything else → work: a dirty `@`, a described-but-empty `@`, a stack of
      described commits under an empty `@`, or an `@` trunk has moved past.
- [ ] Every revset and bookmark target uses the **change id**, never the commit
      id: a snapshot between two of wgo's own jj invocations rewrites the commit
      id but preserves the change id.

### Destination

- [ ] Slug priority: `--name`; an existing non-trunk bookmark on the work;
      a slug derived from the newest description; else `wip-<8-char change id>`.
- [ ] Destination is `<worktrees_dir>/<sanitized-slug>/<repo>` — byte-identical
      to `createWorktree`'s layout, so `wgo to` finds it afterwards.
- [ ] A bookmark is created by default, because wgo keys workspaces on bookmarks
      throughout. `--no-bookmark` opts out.

### The jj sequence

Preflight is entirely read-only and must pass before any mutation, so a rejected
park leaves the operation log untouched. It aborts on: a secondary-workspace
target (naming the main root), a divergent change id, an occupied destination,
a workspace-name collision at a different path, a reused bookmark held by
another workspace, a bookmark name collision, and a conflicted bookmark. A
same-name workspace already at the destination is treated as a resume.

Mutations, in this order:

- [ ] **M1** `BookmarkCreate` — anchors the work by name before anything moves.
- [ ] **M2** `WorkspaceAdd -r <ref>` — populates the destination before the
      source is cleared. jj makes the new working-copy commit a *child* of the
      revset, so at this instant no two workspaces share a change.
- [ ] **M3** `New(trunk)` — returns the clone's `@` to trunk. Must precede M5:
      while both workspaces resolve `@` to the same change, each snapshot
      rewrites the shared commit and stales the other.
- [ ] **M4** `UpdateStale(dest)` — best-effort; M3 advanced the operation head
      and `jj edit` errors in a stale workspace.
- [ ] **M5** `EditChange(dest, ref)` — makes the destination's `@` exactly what
      the clone's was; M2's empty child is auto-abandoned. Failure here is
      non-fatal, since the destination already holds the work.
- [ ] Rollback runs in reverse over completed steps. `jj op restore` is not used:
      it is repo-global and would clobber concurrent work in other workspaces.
- [ ] Every error path names the change and the `jj edit` that recovers it.

### Doctor

- [ ] `wgo doctor` reports work stranded on a main clone's `@`, naming the
      destination and `wgo park <repo>`.
- [ ] `wgo doctor` reports a leftover `<worktrees_dir>/<trunk>/<repo>` workspace.
- [ ] Both checks apply only to main clones, and remain read-only.

## Out of Scope

- **Owner collision.** `<worktrees_dir>/<branch>/<repo>` omits the owner, so
  `orgA/repo1@main` and `orgB/repo1@main` collide, while the PR layout
  `<worktrees_dir>/pr-N-slug/<owner>/<repo>` does include it. Fixing this
  relocates every existing worktree and needs its own migration story.
- **`wgo unpark`.** The symmetric "bring it back" was part of the rationale for
  the `park` name but was not requested.
- **Auto-removing leftover trunk workspaces.** Reported by `wgo to` and
  `wgo doctor`, never deleted.
- **Auto-moving drifted work.** `wgo to` warns; only an explicit `wgo park` moves
  anything.
- **PR worktrees are invisible to discovery** at the default `scan_depth = 4`,
  which is why `findOrCloneRepo` needs its explicit `os.Stat` fallback.
