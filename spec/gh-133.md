# gh-133 — PR triage worklist

**Issue:** https://github.com/dmihalcik-virtru/wgo/issues/133
**Epic:** [gh-96](gh-96.md) · Follow-up, not part of gh-96's acceptance criteria
**Siblings:** [gh-122](gh-122.md) (standup), [gh-120](gh-120.md) (planning)

**Question it answers:** "Which of my open PRs should I land, put back to
draft, or close, and what have I already done about them since I last looked?"

## Summary

Clearing stale and draft PRs is a weekly chore. With a few hundred open PRs
across a dozen repos, it takes several hours and happens mostly on GitHub, not
in a terminal or an agent session. Today you rebuild the list by hand each
time, and an agent rebuilding it costs a full re-query and re-classification
of every PR.

This spec adds a triage view built from facts the dash snapshot already holds,
sorted into buckets by configurable rules. It also adds a **worklist**: a dated
markdown file of those buckets with checkboxes, which you work through over
hours or days. A **resync** ticks off the PRs that are closed or merged and
reports only what changed. wgo only reads the remote; you, or an agent with
your approval, close and convert PRs on GitHub.

## Before this change

- gh-97's PR inventory holds every open PR a configured person authored,
  including the following fields (`PRInfo`, set by `setPRFacts` in
  `internal/dash/inventory.go`):
  - `IsDraft`, `State`, `ReviewDecision`, `Mergeable`, `UpdatedAt`, `CreatedAt`;
  - `BaseRef` and `HeadRef`;
  - `Reviews` (author, state, submitted time) and `ReviewRequests`;
  - linked ticket keys.
- gh-97 facts give each PR a move and reasons (`PRFacts` in
  `internal/dash/facts.go`).
  Those include `draft`, `stale` (`[dash.facts] stale_days`, default 30),
  `no_ticket`, `approved_unmerged`, `conflicts` and `ci_failing`. gh-98 gives
  tickets a status and the `ticket_done_code_open` mismatch.
- Nothing tells a human review apart from a bot review, so an x-test or
  SonarCloud comment counts as activity and keeps a PR looking alive.
- Nothing marks a PR whose base is another of the operator's open PR
  branches. Closing the bottom of a stack without seeing that strands the PRs
  above it.
- `wgo pr` lists open PRs but cannot classify them, persist a list, or diff
  against a previous look.

## Requirements

### Facts

1. **Human activity.** For each PR, add `human_activity`: the latest
   review by someone other than the author whose login does not match
   `[pr.triage] bot_logins`, a list of case-insensitive regexes. (The
   inventory holds reviews, not comments.) Its default covers `[bot]`
   suffixes, `github-actions`, `sonarqubecloud`, `codecov`, `dependabot`,
   `renovate`, and the review bots `gemini`, `copilot` and `coderabbit`.
   Also add `human_reviewer`: the logins of those reviewers; worklist
   rows show each with their latest review state. If reviews were not fetched, the fact is unknown, not "none".
2. **Approval dismissed.** `approval_dismissed` is true for an open PR whose
   review decision is `REVIEW_REQUIRED` while a human's latest review is
   `APPROVED` or `DISMISSED`. An empty review decision (no review required)
   makes it false. These PRs
   need a fresh review, not a merge.
3. **Stack position.** `stacked_on` holds the open PRs of the same
   repository whose head is this PR's base, normally zero or one.
   `stack_children` lists the open PRs based on this PR's head. Both come
   from `BaseRef` and `HeadRef` in the inventory, matched by name; a head in
   a fork or on the repository's default branch is never a stack's base.
4. **Linked-ticket fields on the PR.** gh-100 fields belong to one node kind,
   so a PR rule cannot read its ticket's status. Add PR fields
   `ticket_category` (set of the linked tickets' `status_category`) and
   `ticket_sprint_state` (set of their sprints' states). They are unknown when
   a linked ticket was not fetched, and empty when the PR links no ticket.
5. **Registry.** Register these gh-100 fields for kind `pr`:

   | Field | Type |
   |---|---|
   | `human_activity` | date |
   | `human_ago` | duration (days since `human_activity`) |
   | `human_reviewer` | set of logins |
   | `approval_dismissed` | bool |
   | `stacked_on` | set (zero or one PR) |
   | `stack_children` | set of PRs |
   | `ticket_category` | set, enum `todo in_progress done` |
   | `ticket_sprint_state` | set, enum `active future closed` |

### Buckets

6. **Rules.** `[[pr.triage.rules]]` entries, evaluated in order, put each open
   PR the operator authored into the first bucket whose rule matches. A rule
   has a `bucket` name, an optional `note`, and a `match` written in gh-100's
   query language over PR fields, for example `ticket_category:done` or
   `!ticket:*;updated_ago:>180;!human_ago:<=180`. The last rule, and only
   the last, has no `match`: it takes every PR no earlier rule matched, so a
   PR whose fields are unknown never falls into a bucket that asserts
   something about it. A bucket name must read back the same from a worklist
   heading (no Markdown punctuation, `" ("` or `New since` prefix). If a
   field a rule needs is unknown for a PR, the rule does not match; that PR's
   row in its final bucket names the unknown field.
7. **Default rules**, used when none are configured, in order (`<S>` is
   `[dash.facts] stale_days`):

   | Bucket | `match` | Action it suggests |
   |---|---|---|
   | `land` | `review:approved;!prstate:draft`, or `approval_dismissed:true` | merge, fix what blocks it, or re-request review |
   | `keep` | `ticket_sprint_state:active` | none |
   | `close?` | `ticket_category:done;!ticket_category:todo,in_progress` | close if superseded |
   | `close?` | `!ticket:*;updated_ago:>180;!human_ago:<=180` | close if abandoned |
   | `draft?` | `!prstate:draft;stale:true` | ping a reviewer or convert to draft |
   | `fix ticket` | `updated_ago:<<S>;ticket_category:todo` | move the ticket; the code is moving |
   | `active` | `updated_ago:<<S>` | none |
   | `parked` | everything else (stale drafts, ticket not done) | none until the work is dropped |

   A row with two `match` values is two rules with the same bucket. The `?`
   marks a suggestion. No bucket name implies that wgo acts. The first
   `close?` rule needs every linked ticket done, so a PR shared by a done
   and an open ticket is not offered for closing. The second uses
   `!human_ago:<=180` so a PR no human ever reviewed still matches. On one
   operator's 216 open PRs these rules put 74 in `fix ticket` and 56 in
   `parked`: separating "Jira is behind the code" and "nothing to do this
   week" from the PRs that need a decision is most of the value.
8. **Stack guard.** A PR with `stack_children` shows its children next to
   it, in every bucket, so a `close?` row says it is the base of other open
   PRs.

### Worklist

9. **Write.** `wgo pr triage` writes
   `~/.wgo/triage/<YYYY-MM-DD>-prs.md`, or the path given with `-o`. It then
   prints the path and the count in each bucket. The file has:
   - a header with the snapshot time and freshness of each source;
   - an **Incomplete** line naming the open-authored inventory set when its
     fetch failed, was cut short by the search limit or was partly read, and
     each linked ticket with no status, so a missing PR never reads as
     closed. The inventory is one cross-repo search per person, so a gap is
     named per set, not per repo;
   - one `##` section per bucket, holding its `note` and count;
   - one item per PR, `- [ ] [repo#N](url) draft|ready · updated <date> ·
     [TICKET](url) <status> · <human reviewers> · <title>`, with an extra
     `stack: base of #M, #K` when requirement 8 applies and
     `unknown: <fields>` when a rule could not be decided.

   An existing file is not overwritten without `--force`; it may hold notes.
   `--cached` makes no remote lookups. Inventory PRs that the last refresh
   no longer found open, but that the closed-PR search has not reached yet,
   are left out rather than shown as open.

   Links are markdown, so terminals and editors render them as OSC 8.
10. **Human-editable.** The file stays valid if you edit it by hand. Anything
   that is not an item line is kept as written: notes under items, reordered
   sections, extra headings. An item is recognised by the
   `- [ ] [label](https://github.com/owner/repo/pull/N)` prefix alone.
11. **Resync.** `wgo pr triage --resync [path]` defaults to the newest
   worklist. It:
   - re-reads open PRs (one inventory refresh, the same bound as
     `wgo dash --json --refresh`);
   - ticks `[x]` and appends ` · closed <date>` or ` · merged <date>` to each
     unticked item whose PR is no longer open (` · no longer open` when the
     snapshot does not hold its closed state). It ticks nothing while the
     open PR list is incomplete, since a missing PR may still be open, and
     never ticks a PR the snapshot still holds open, such as a teammate's
     PR added by hand;
   - appends a `## New since <date>` section with open PRs that are not yet
     in the file, bucketed by the rules;
   - leaves items you ticked yourself alone, even while the PR is still open;
   - reads the file after the refresh and replaces it atomically, so edits
     saved meanwhile are kept, and refuses a file that is not a worklist.

   It prints the newly closed and merged PRs, the unchecked count per bucket,
   and the new PRs. This output is meant to be the whole context an agent
   needs to continue a triage pass.
12. **Draft drift.** Resync flags each unticked item whose PR the rules now
    put in a bucket other than its section's: a `draft?` PR made a draft
    again, a `land` item that lost its approval.
13. **JSON.** `--json` prints the buckets and items, or with `--resync` the
    resync result, and writes no worklist unless `-o` is given (with
    `--resync`, it writes nothing), so agents and scripts can read them
    without parsing markdown or changing the operator's file.

### Dash view

14. **View.** An addon `web/live-triage.js`, registered as `triage`, shows the
    buckets as sections. Each row has its facts and links, and each section
    has a count. It refreshes with the snapshot, so PRs you close on GitHub
    drop out without running a command. A PR closed since the page loaded
    shows struck through until the next "mark seen".
15. **Extract.** `/api/extract?view=triage&q=<query>` and
    `wgo dash --md --view triage` print the same buckets with the same
    renderer as requirement 9, minus the checkboxes.

## Open questions

- Should the worklist record the operator's decision per item, for example
  `keep`, so the next week's run can skip it? The default here is no: next
  week's rules re-derive it, and you can add a note by hand.
- Should resync ever write to GitHub, for example to convert `draft`-bucket
  items back to draft? The default is no (see Out of scope). A skill or agent
  can do it with the operator's approval.

## Out of scope

- Closing, merging, converting or commenting on PRs. wgo stays read-only
  against GitHub and Jira; see AGENTS.md "Non-destructive".
- PRs authored by other people, except as stack children of the operator's
  PRs.
- Scheduling the weekly run. An agent or cron can call `wgo pr triage`.

## Acceptance criteria

- [ ] `human_activity` ignores reviews from logins matching
      `bot_logins` on the fixture. It is unknown when reviews were not
      fetched.
- [ ] `approval_dismissed` is true for a fixture PR with a human `APPROVED`
      review and a current decision of `REVIEW_REQUIRED`.
- [ ] `stacked_on` and `stack_children` are right for a three-PR fixture
      stack. A `close?` item that is the base of the stack names its children.
- [ ] `ticket_category` is empty for a PR with no ticket and unknown for a PR
      whose ticket was not fetched. A rule that needs it does not match the
      second PR, and that PR's row names the unknown field.
- [ ] The default rules put each fixture PR in the expected bucket. A
      configured rule list replaces them, and an invalid `match` is a config
      error that names the rule.
- [ ] `wgo pr triage` writes a worklist whose item lines parse back to the
      same PR set. Hand-added notes and reordered sections survive
      `--resync`.
- [ ] `--resync` ticks closed and merged PRs, adds new ones under
      `## New since`, and leaves hand-ticked open PRs ticked. A second
      resync with no changes reports nothing new.
- [ ] When the open-authored PR list fails, is cut short or is partly
      read, the worklist and `--json` name it as incomplete, and resync
      ticks nothing.
- [ ] `--json` and the markdown agree on bucket counts for the same snapshot.
- [ ] The dash triage view, `/api/extract?view=triage` and
      `wgo dash --md --view triage` agree on bucket counts for the same
      snapshot and query.
- [ ] Keyboard-only use and a colour-vision-deficiency simulation pass
      (screenshots from a sandbox HOME in the PR, light and dark).
- [ ] `go test ./...` passes.
