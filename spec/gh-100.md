# gh-100 — Query language, URL state, CLI query and Markdown extract

**Issue:** https://github.com/dmihalcik-virtru/wgo/issues/100
**Epic:** [gh-96](gh-96.md) · **Wave 1** · Unblocks gh-101, gh-102, gh-103, gh-104, gh-105

## Summary

Define one filter language for the dash and use it everywhere: in the URL
hash (so every view is a link and back/forward is history), in `wgo dash
--query`, in saved filters, and as the state behind every chart click. Add a
Markdown extract of the current view, and the registries that let later views
ship as separate files. This spec works on the snapshot fields that exist
today; gh-97, gh-98 and gh-99 add fields to its registry.

## Before this change

- The page holds a single filter `{by, value}` with `by` ∈ `day`,
  `prstate`, `effort` (`internal/review/web/live.js:68`); choosing a second
  bar replaces the first, choosing the same bar clears it (`:93`). The
  visible set is the filter's seeds plus everything they lead to and
  everything leading to them (`L.closure`, `:46`).
- The search box selects substring matches over label and ID (`:267`); it
  does not filter.
- Only `#view=table` is read from the URL (`:1405`); nothing is written.
- `wgo dash --json` prints `{snapshot, delta}` (`internal/dash/live.go:116`);
  there is no filtering and no Markdown.
- The live page is one script, `live.js` (1,400 lines). `review.Page.Addons`
  (`internal/review/web.go:42`) can inline further scripts after it.
- Pure logic in `live.js` is tested under node by
  `internal/review/livejs_test.go` with `testdata/live_logic.js`.

## Requirements

### Field registry

1. `internal/dash/fields.go` defines the canonical registry. Each field has:
   `name` (query name), `label`, `type` (`enum`, `set`, `number`,
   `duration`, `date`, `text`, `bool`), `kinds` (node kinds it applies to),
   `paths` (JSON paths into a node; several paths mean "any of"), an optional
   `derive` (`days_since`, `count`, `activity_days`, `linked_repos`, or
   `efforts`). `efforts` yields the keys of the efforts the node belongs to,
   by walking edges backwards like `L.effortsOf`
   (`internal/review/web/live.js:96`). `linked_repos` yields a ticket's
   repositories from its incoming PR and bookmark edges; a ticket with no
   such edge has an unknown repo. Each field
   also has `unit`, optional ordered `values` for closed enums, and a `scale`
   hint (`linear` or `log`) for charts.
2. The page receives the registry in its bootstrap
   (`internal/dash/page.go:18`), with `me` (the authenticated login) and
   `people` (gh-97). The JS evaluator implements the same small set of `derive`
   functions. `activity_days` is the union of local activity dates in the
   efforts a node belongs to. Durations derive from timestamps relative to
   the snapshot's `generated_at`, so a snapshot always gives the same answer.

### Grammar

4. A query is clauses joined by `;` (AND). A clause is `[!]name:operand`.
   Only the first `:` separates name from operand, so
   `move_people:team:web` works.

   ```text
   query    = [ clause *( ";" clause ) ]
   clause   = [ "!" ] name ":" operand
   operand  = "*" / range / list
   list     = value *( "," value )            ; OR within a clause
   range    = [ bound ] ".." [ bound ] / cmp bound
   cmp      = ">=" / "<=" / ">" / "<"
   bound    = number [ "d" / "w" ] / date / relative
   date     = 4DIGIT "-" 2DIGIT "-" 2DIGIT    ; local calendar day
   relative = "today" / ( "-" / "+" ) 1*DIGIT ( "d" / "w" )
   value    = token / DQUOTE *( qchar ) DQUOTE
   token    = 1*( ALPHA / DIGIT / "-" / "_" / "." / "/" / "@" / "#" / "+" / ":" )
   ```

   - `*` holds when the field is known and non-empty.
   - Macros: `@me` (authenticated login) and `@people` (every configured
     login) expand in both evaluators.
   - Relative dates and durations resolve against the snapshot's
     `generated_at`. Duration bounds are days; `2w` = 14 days.
   - `text` is a case-insensitive substring match over label, title and ID.
5. Three-valued logic: a clause on an unknown value is **not** a match,
   negated or not. Closed enums accept the literal `unknown`, so the operator
   can include unknowns explicitly (`mergeable:mergeable,unknown`). Facets
   (gh-102) show unknown as its own bucket.
6. Errors give the position and a fix: unknown field → the closest field name
   plus the list; a value outside a closed enum → the allowed values; a range
   on a non-ordered field → which fields take ranges.

### Semantics

7. A clause **applies** to a node when the node's kind is in the field's
   `kinds`. A node **matches** only when every non-`kind` clause applies to
   it and holds. A query with no non-`kind` clauses matches every node. A
   combination of fields with no common applicable kind is a query error
   that names the incompatible fields; it never silently drops a clause.
   Validate the common kinds against any `kind:` row restriction too.
8. `kind:` clauses restrict which matches are **rows** (table rows, chart
   marks); they do not create matches.
9. The **visible** set (graph, efforts list) is `L.closure` of the matches, as
   today. An empty query means no filter (`vis = null`).
10. Today's chart clicks become clauses: a day bar sets `activity:<date>`, a
    PR-state bar sets `prstate:<bucket>`, an effort bar sets
    `effort:<key>`. A click replaces any existing clause on the same field
    and leaves other clauses alone; clicking the active value removes the
    clause. (gh-102 adds multi-value and exclusion gestures.) Because `effort`
    applies to every kind, an effort filter still matches everything in the
    effort. Because `activity` also applies to nodes through their efforts,
    combining a day and a PR-state bar selects PRs in efforts active that
    day. The graph and efforts list show the visible closure; the table
    shows additional closure nodes as dimmed context rows (gh-101).

### Shared test vectors

11. `internal/dash/testdata/query_vectors.json` holds a small invented
    snapshot and cases `{name, query, expect: {matches, rows}}` or `{name,
    query, error}`. The Go evaluator (`internal/dash/query.go`) runs them in
    `go test`; the JS evaluator runs the same file through
    `internal/review/testdata/live_logic.js`. A case that passes in one
    runtime and fails in the other fails CI. Include cross-kind combinations:
    `activity:<date>;prstate:open` matches only PRs in active efforts;
    `repo:acme/api;status_category:done` matches only linked tickets in that
    repository; `prstate:open;status_category:done` reports incompatible
    fields.

### URL state and history

12. The hash holds `view`, `q` (percent-encoded query), `sort`, `cols` and
    `sel` (selected node IDs). Other specs may add keys; unknown keys are
    preserved.
13. A committed change (click, Enter, end of a drag) calls `pushState`;
    changes during a drag or while typing call `replaceState`. Back and
    forward restore query, view, sort, columns and selection. The existing
    `#view=table` links keep working.
14. A query bar shows the current query as editable text: Enter applies,
    errors appear inline with their fix, Esc reverts. The search box keeps
    its current select-by-substring behaviour.

### CLI

15. `wgo dash --json --query EXPR` adds `"query": {"expr", "matches",
    "rows"}` to the output and limits `snapshot.nodes` and `edges` to the
    visible set. Without `--query`, the output is unchanged.
16. `wgo dash --md [--query EXPR] [--cols a,b] [--group effort|repo|none]
    [--view rows|sprint] [--sprint ID]` prints the Markdown extract (below)
    and exits without serving. `rows` is the default. `--view sprint` and
    `--sprint` become available with gh-105; before then they give an
    explanatory unavailable-view error.
17. `wgo dash --query EXPR` (without `--json` or `--md`) serves and opens the
    browser at `#q=EXPR`.
18. `--preset NAME` stands for `--query` with a saved filter's expression;
    giving both is an error.
19. Query errors exit non-zero, show the error with its position, and
    suggest a corrected command.

### Saved filters

20. `[dash.filters]` in config maps names to expressions. Built-in filters
    live in `internal/dash/filters.go`; a config entry with the same name
    overrides one. The page gets the merged list in its bootstrap.
21. A built-in whose fields are not registered yet (its data spec has not
    landed) is hidden, and `--json` reports why.
22. Built-ins:

    | Name | Expression |
    |---|---|
    | `my-move` | `move_people:@me` |
    | `waiting-reviewers` | `kind:pr;move:reviewer` |
    | `push-reviewers` | `kind:pr;move:reviewer,nobody;ci:green,systemic_only` |
    | `nobody` | `kind:pr;move:nobody` |
    | `review-inbox` | `kind:pr;requested_from:@me` |
    | `shipped` | `kind:pr;prstate:merged;merged:-7d..` |
    | `close-candidates` | `kind:pr;prstate:open,draft;updated_ago:>=90` |
    | `jira-out-of-sync` | `kind:ticket;mismatch:*` |
    | `sprint` | `kind:ticket;sprint_state:active` |

### Markdown extract

23. `internal/dash/extract.go` renders the rows of a query as Markdown: an
    optional heading (the saved filter's name, else the expression), sections
    by effort or repository, one bullet per row — linked label, title, then
    the chosen columns as `name: value` separated by `·` — and a provenance
    footer: snapshot time, each source's freshness, the query, and "n of
    total". Unknown values print as `unknown`, never blank. `--layout table`
    prints a GitHub-flavoured table instead of bullets.
24. `GET /api/extract?q=&cols=&group=&layout=&view=&sprint=` returns the same
    Markdown from the held snapshot. `view=rows` is the default; gh-105 adds
    `view=sprint` with `sprint=<id>` and the matching CLI renderer. Like every
    GET route, it runs no discovery, jj, process or network call.
25. The page has a "Copy as Markdown" button that fetches `/api/extract` for
    the current state and copies the result with `navigator.clipboard`,
    falling back to a selected text area. It works under the existing CSP
    (`internal/dash/page.go:87`).

### Extension seams

26. `window.WGOLive` gains `registerView({id, label, question, render(ctx),
    destroy()})` and `registerPanel(...)` for overview panels. `ctx`
    provides the store (snapshot, index, query result, selection,
    `subscribe`), `setQuery(expr, {commit})`, `select(ids, add)`, theme
    tokens and the existing DOM helpers. View tabs come from the registry; the
    graph and table register through it too.
27. The live page inlines addon scripts listed by the dash
    (`review.Page.Addons`), and `live.js` starts after they have registered.
    gh-101 to gh-105 add their views as addons.

### Performance

28. Field values are indexed once per snapshot. Evaluating 12 clauses over
    2,000 nodes takes under 10 ms in node on the gh-97 fixture generator (or a
    local generator if gh-97 has not landed). The measurement is logged by the
    test and reported in the PR, not asserted.

## Out of scope

- Facet panels, multi-value gestures and coupled counts (gh-102).
- New views (gh-101, gh-103, gh-104, gh-105).
- Writing saved filters from the browser. The page can copy a config snippet
  (gh-102); config stays hand-edited.
- OR across clauses, parentheses, or free boolean expressions.

## Acceptance criteria

- [ ] The grammar parses every example in this spec; malformed queries fail
      with a position and a fix.
- [ ] The shared vectors pass in both Go and node, covering every type,
      macros, relative dates, `*`, negation, unknowns, `kind` as a row
      filter, and cross-kind combinations without ignored clauses.
- [ ] Clicking each existing chart bar yields the clause in requirement 10;
      clicks on different charts combine with AND.
- [ ] The hash round-trips: reloading a URL restores query, view, sort,
      columns and selection; back and forward step through committed changes.
      `#view=table` still works.
- [ ] `wgo dash --json --query`, `--md`, `--preset` and `--query` alone
      behave as specified; errors suggest a fix.
- [ ] `/api/extract` matches `wgo dash --md` byte for byte for the same
      snapshot and arguments, and passes the GET purity tests.
- [ ] A team-only review request for the authenticated person matches both
      `my-move` and `review-inbox`. A merged PR updated in a different week
      matches `when:` only for its merge week.
- [ ] "Copy as Markdown" works under the CSP in Safari, Chrome and Firefox.
- [ ] Graph and table are registered views; an addon view registered by a
      test script appears as a tab.
- [ ] `go test ./...` (including `TestLiveJSLogic`) and `go vet ./...` pass.
