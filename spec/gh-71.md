# gh-71 — Parse and author plan efforts

**Issue:** https://github.com/dmihalcik-virtru/wgo/issues/71
**Split from:** [gh-70](gh-70.md), which consumes this attribution.

## Summary

Make efforts a populated, human-editable grouping. Parse the `## Efforts`
section of `~/.wgo/plan.md`, author it through narrow commands, and attribute
each workspace to an effort deterministically or report why it cannot.

## Problem (before this change)

- `internal/store/state.go` defined `Effort` and `State.Efforts`, but no
  command populated them.
- `plan.Parse` kept only `## Active Branches`, `## Tasks` and `## Notes`.
  Every save path (`add`, `done`, `plan`, `join`, `spec`) called
  `SavePlan(p.Render())`, which regenerated the whole file. A hand-written
  `## Efforts` section, or any other custom section, was **deleted on the next
  write**. This was an existing data-loss bug, not only a missing feature.
- `Plan.Render` iterated `p.Efforts` as a map, so effort order was
  nondeterministic between writes.

## Requirements

### Section-preserving plan writer

1. Parse `## Efforts`: `### <heading>` per effort, an optional description
   paragraph, and `- repo:bookmark` entries. Parse tolerantly.
2. Keep every section the parser does not own, in its original position and
   byte-for-byte. Only owned sections are re-rendered.
3. Render efforts in a stable order: file order for efforts already in the
   file, then new efforts by name.
4. Move every `SavePlan(p.Render())` caller onto the preserving writer.

### Authoring and reconciliation

5. Add `wgo plan effort add|link|unlink|remove`. Each updates `State.Efforts`
   under `MutateState` and the `.plan` projection.
6. A manual `.plan` edit wins over the same effort's projected fields on the
   next read. Ambiguous or malformed entries produce a diagnostic and are kept,
   not discarded. State-only efforts remain readable. Read-only commands never
   rewrite `.plan`. (`wgo today` syncs Active Branches into the plan; it does so
   through the same preserving writer and is not a read-only command.)
   When state and the plan disagree about an effort's entries, attribution
   reports it.
6a. Commands never destroy hand-written content silently:
    - `remove` refuses, without `--force`, when the effort's block holds
      malformed entries or stray text, and lists them.
    - `add` errors rather than dropping a `--description` that conflicts with an
      existing effort, and matches existing names case-insensitively.
    - `unlink` can drop a reference whose clone is no longer discovered.
    - Inserting an entry keeps a hand-written nested list with its parent entry.
    - A plan effort entry is `repo:bookmark`, split at the last colon, so an
      absolute clone path with spaces round-trips. Names and descriptions that
      would read back as headings or entries are rejected.

### Identity

7. An effort's persisted map key is its stable ID. For an effort authored only
   in `.plan`, derive the ID from its normalized heading plus a short hash of
   the heading alone. Changing the description keeps the ID. Renaming the
   heading deliberately creates a new ID. Duplicate headings are reported as
   ambiguous.

### Attribution

8. Normalize legacy `repo:bookmark` values to a discovered repository's main
   clone and exact bookmark before matching. Never match a bookmark by name
   alone across repositories.
9. Explicit agent `ThemeID` (from [gh-72](gh-72.md)) wins. Otherwise resolve
   workspace → main clone → current bookmark → effort membership.
10. A bookmark no effort claims groups under its parsed ticket ID (`GH-70`,
    `WGO-123`), then under **Ungrouped**. A bookmark claimed by several
    efforts is an attribution conflict shown in Ungrouped. A workspace with no
    bookmark stays visible in Ungrouped. Never infer a theme from a similar
    name.
11. Expose attribution as a package-level function returning groups plus
    diagnostics (`internal/effort`), so `wgo status`, `wgo .` and the dashboard
    can share it. Nothing outside tests calls it yet; those consumers land with
    [gh-70](gh-70.md).

## Acceptance criteria

- [x] A hand-edited `## Efforts` section and an unrelated custom section
      survive `wgo add`, `wgo done`, `wgo plan add` and `wgo join` unchanged.
- [x] Efforts render in deterministic order.
- [x] `wgo plan effort add|link|unlink|remove` round-trips through state and
      `.plan`.
- [x] Manually edited `.plan` efforts and state-only legacy efforts both group
      work.
- [x] Every workspace has deterministic attribution or a visible ambiguity or
      conflict warning.
- [x] No cross-repository match on bookmark name alone.

## Verification

- Golden-file round-trip tests for plan files with custom sections, malformed
  effort entries and duplicate headings.
- Command tests that run each `SavePlan` caller against a plan containing a
  custom section.
- Attribution tests using `internal/jjtest` repositories with the same
  bookmark name in two repositories.
- `go test ./...`, `go vet ./...`, `gofmt`.

## Out of scope

- Dashboard rendering ([gh-70](gh-70.md)).
- Agent session storage ([gh-72](gh-72.md)).
- Guessing semantic theme equivalence from names.
