# gh-101 — Analysis table

**Issue:** https://github.com/dmihalcik-virtru/wgo/issues/101
**Epic:** [gh-96](gh-96.md) · **Wave 2** · Needs gh-97, gh-99 and gh-100 for
the PR default columns and graphics

**Question it answers:** "Across the rows I have filtered, how do they
compare, and which come first by the measure I care about?"

## Summary

Make the table the workhorse for comparing many items: columns chosen from
the field registry, multi-key sort, and word-sized graphics (Tufte) in cells —
bars for age and waiting time, a log-scale size bar, one mark per CI check,
and review glyphs — with the number or word always beside the mark. Dense,
quiet and keyboard-first.

## Before this change

- The table has six fixed columns — Name, Kind, Effort, State, Data, Last
  activity (`internal/review/web/live.js:961`) — single-key sort, and grid
  keyboard navigation (`:960`–`:1010`). It lists every visible node,
  including the efforts and workspaces that a filter keeps as context.

## Requirements

### Columns

1. The table is an addon view (`web/live-table.js`) registered through gh-100,
   replacing the built-in table with the same keyboard behaviour (arrows
   move, Enter/Space selects, Shift+Enter adds).
2. Columns come from gh-100's field registry. A column chooser lists every
   field that applies to the current rows' kinds; columns can be added,
   removed and moved left or right by keyboard and pointer. Column state is
   in the URL (`cols=`).
3. Default columns depend on the rows' kinds:
   - only PRs: ref and title, repo, author, move, waiting, age, size, CI,
     reviews, tickets;
   - only tickets: key and summary, status, assignee, points, sprint, linked
     PRs, mismatch;
   - mixed: today's six columns.
4. Rows are gh-100's **rows** (matches limited by `kind:`). Context rows — kept
   only because a match leads to them — are hidden when a `kind:` clause is
   present, and otherwise shown dimmed, with a toggle.

### Sorting

5. Clicking a header sorts by it; clicking again reverses; Shift+click adds a
   secondary (then tertiary) key. Sort state is in the URL (`sort=-waiting,
   size`) and shown in each header with direction and rank.
6. Unknown values sort last in both directions and render as `unknown`, never
   as blank or zero.

### Word-sized graphics

Each graphic sits beside its value as text and has an `aria-label` sentence;
none encodes by colour alone.

7. **Durations** (`age`, `waiting`, `updated_ago`): a thin horizontal bar,
   linear, zero-based, on a scale shared by the column, with the value
   (`12d`).
8. **Size**: a bar on a log scale shared by the column, with `+120 −30`. The
   header tooltip says "log scale".
9. **CI**: one small mark per check, failures first: failing is a filled mark
   with `×`; failing but systemic (gh-99) is a hollow mark with `~`; pending is
   `·`; passing is a small neutral tick; skipped is omitted. At most 20 marks,
   then `+n`. Label: "3 failing (2 fail everywhere), 25 passing".
10. **Reviews**: one glyph per reviewer — `✓` approved, `✕` changes
    requested, `○` requested and outstanding, `…` commented — with the login;
    teams show as `team:<slug>`.
11. **Move**: the word (`you`, `reviewer`, `nobody`, `author`). The accent
    colour is used only when the move is the operator's (`move_people`
    contains `@me`).
12. Numbers are right-aligned with tabular figures. Rows are compact (about
    24 px), with light horizontal rules, no zebra fill, a sticky header and a
    sticky first column.

### Coupling and extract

13. Selecting rows selects nodes in every view; hovering a row highlights its
    node in the graph and in charts (gh-103) — the existing store.
14. "Copy as Markdown" (gh-100) uses the table's visible columns and sort.

### Performance

15. Rendering 2,000 rows takes under 100 ms; beyond 500 rows the table
    renders only the rows in view plus a margin. Measured on the fixture
    generator and reported in the PR.

## Out of scope

- Editing values in place.
- Column-level aggregates (sums, medians) beyond what facets (gh-102) show.
- Saving column layouts to config (the URL carries them).

## Acceptance criteria

- [ ] The column chooser adds, removes and reorders columns with keyboard
      only; state survives reload through the URL.
- [ ] Multi-key sort works, shows rank, and survives reload; unknown sorts
      last.
- [ ] Each word-sized graphic renders from the fixture with its text value
      and an `aria-label`; a screenshot in the PR shows PR and ticket
      defaults in light and dark themes.
- [ ] With `kind:pr` set, only PR rows appear; without it, context rows are
      dimmed and can be hidden.
- [ ] Existing keyboard behaviour is preserved (tests in
      `internal/review/testdata/live_logic.js` for the pure parts: column
      defaults, sort comparator, unknown ordering, CI mark ordering).
- [ ] 2,000-row render time is reported in the PR and is under 100 ms.
- [ ] `go test ./...` passes.
